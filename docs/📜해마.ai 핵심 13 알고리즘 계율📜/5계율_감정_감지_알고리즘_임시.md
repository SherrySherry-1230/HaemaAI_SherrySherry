# 5계율 — 감정 총량·과거 사건·입력 변화 판단 알고리즘

> **기획 명세이며 구현 완료를 뜻하지 않는다.** 입력 중 변화를 감정의 확정 사실로 취급하지 않는다.
> 아래 판단 기록은 설명용이며 구현된 API 타입이나 새 저장 필드가 아니다.

## 역할과 읽는 상황

최종 사용자 발화에서 관련 쩜에 드러난 감정과 과거 사건의 영향을 누적한다. 별도로, 입력 중에는 연속된 스냅샷에서 망설임이나 정서 변화의 **가능성**을 찾는다.
발화가 확정되면 임시 판단을 최종 문장과 대화 맥락에 다시 비춰 본다.
감정 진단, 상대 의도 추정, 호스트의 최종 답변 생성은 맡지 않는다.

- 읽는 때: 입력 중 새 스냅샷이 들어올 때와 전송 버튼·Enter로 발화가 확정될 때.
- 검색어: `스냅샷`, `타이핑 간격`, `삭제·재작성`, `망설임`, `감정 변화 가능성`, `최종 발화`.
- 협업: [1계율 쩜 추출](./1계율_쩜_추출_알고리즘.md)이 발견한 사건·관계 후보의 맥락을 보조한다.
- M1/M2 웹 콘솔은 실제 호스트 연동 전에 입력 상황을 관찰·시뮬레이션하는 자리다.

## 확정된 감정 총량 계산

긍정·부정 모두 영향의 양으로 더한다. 반대 감정이 생겼다고 서로 상쇄하지 않는다. 별도 설명이 없으면 쩜 생성 이후의 대화부터 계산하고, 사용자가 말한 과거 사건은 생성 전이라도 따로 반영한다.

| 현재 사용자 발화에서 관련 쩜에 드러난 정도 | AI가 골라 더할 값 |
| --- | ---: |
| 감정이 있음·언급이 있는 정도 | 1 |
| 같은 발화의 다른 쩜보다 특별한 감정 | 2 |
| 강한 감정 | 3 |

한 번의 평가에서 **1·2·3 중 하나**를 골라 기존 총량에 더한다. 예를 들어 별도 발화에서 1, 3, 2점이면 총 6점이다. 입력 중 스냅샷이나 같은 최종 발화의 재처리는 새 감정 발생으로 집계하지 않는다. N에 제외되는 따라 답하기라도 사용자의 감정이 드러나면 이 항은 평가한다. 호스트의 표현을 사용자의 감정으로 대신 세지 않는다.

| 과거 사건의 의미 | 현재 감정과 별도로 더할 값 |
| --- | ---: |
| 해당 쩜에 대한 판단을 바꿀 만한 과거 단일 사건 | 303 |
| 여러 사건으로 점진적으로 인식이 변함 | 사건 하나당 33 |

**동일한 과거 사건의 사건 점수는 해당 쩜에 한 번만 더한다.** 다른 날 다시 말하면 그때의 감정 1~3점만 추가한다. 같은 사건인지, 별개 사건인지, 어떤 쩜에 영향을 주는지는 해마.ai가 문맥으로 판단한다. 관련 과거 사건 자체도 쩜으로 만들며, 이미 있는 사건이면 [2계율](2계율_기존_쩜_탐색_알고리즘.md)에서 찾아 재사용한다. 저장부는 AI가 연결한 사건과 대상 쩜의 가산 이력을 확인해 재처리를 막는다. 실제 저장 필드는 별도 설계한다.

### 회의에서 논의한 사례 · 최O희와 생일파티

기획팀 회의에서 논의한 사례: 소중하고 좋게 생각하던 친구 최O희가 생일파티를 밤새 함께하기로 했으나, 인사한 뒤 몸이 아프다고 말하고 떠났다. 사례 속 화자는 이미 호텔 방을 업그레이드해 체크인한 상태였다. 이름은 영문 대문자 O로 가렸다.

- 기존 **최O희 쩜:** 관계에 대한 판단을 바꿀 만한 사건으로 반영하므로 최초 사건 점수 **+303**과 이번 발화의 감정 **+1~3 중 AI가 판단한 값**을 더한다. 긍정적으로 쌓인 이전 감정 총량을 지우거나 음수로 바꾸지 않는다.
- **‘생일파티 배신사건’ 쩜:** 개인적 사건 쩜을 생성하고 최O희 쩜과 연결한다. ‘배신’은 기획팀 회의에서 논의한 사례 속 화자가 느낀 의미로 기록하며 친구의 건강 상태나 의도를 새로 단정하지 않는다. 연결 굵기는 AI가 판단한다.
- **사건 쩜의 파워:** 사건도 독립된 쩜이므로 자신의 언급·노출 기간·감정·연결 합을 계산한다. 친구의 +303이나 총파워를 사건에 그대로 복사하지 않는다. 사건 쩜에 반영할 감정·과거 사건 근거도 AI가 따로 판단한다.
- **나중에 재언급:** AI가 같은 생일 사건 쩜을 찾아 재사용한다. 이미 반영한 +303을 다시 더하지 않고 새 발화의 감정만 누적한다. N은 별도로 사용자 선행 언급 규칙을 적용한다.

이는 기획팀 회의 내용을 바탕으로 정리한 기획 사례이며 외부 사실 검증·실제 기억 저장 결과가 아니다. 네 항의 계산은 [10계율](10계율_중요도와_우선순위_알고리즘.md)을 따른다.

## 필요한 입력과 경계

1. 같은 입력 흐름의 이전·현재 텍스트 스냅샷과 각각의 시각.
2. 수정·삭제·멈춤·재개·전송 여부. 제공되지 않은 신호는 추정하지 않는다.
3. 앞뒤 대화와 이미 관련이 확인된 쩜(JJum)의 식별 정보.
4. 아직 입력 중인지, 유저가 최종 발화로 확정했는지에 관한 구분.
5. 호스트가 준 `hint`가 있다면 참고하되 Haema는 서비스별 `meta` 내용을 해석하지 않는다.

입력 속도나 멈춘 시간만으로 슬픔·분노·불안 등을 확정할 수 없다.
느린 입력은 다른 일, 접근성 도구, 통신 지연 등으로도 생길 수 있다.
한국어의 `ㅋㅋ`·`ㅎㅎ`·`ㅠㅠ`·말줄임표, 존댓말·반말·호칭·주어 생략도 문맥 없이 감정이나 친밀도를 확정하는 표지가 아니다.
스냅샷은 수정 가능한 초안이므로 삭제된 표현을 유저의 확정 발언으로 인용하지 않는다.
기획서의 0.5초 논블로킹 스냅샷은 입력과 시각의 수신 간격이며 매번 감정 의미 분석이나 모델 호출을 요구하지 않는다. 이 문서가 새 타이머를 정의하지 않는다.

## 판단 순서와 분기

### 1. 출처와 순서 확인

같은 입력 흐름인지, 시각 순서가 정상인지, 내용이 실제로 달라졌는지 본다.
누락·역순·중복 수신이면 변화의 원인을 꾸며내지 않고 해당 비교를 보류한다.
호스트 답변이나 다음 발화를 현재 입력의 스냅샷으로 섞지 않는다.

### 2. 관찰 가능한 변화만 적기

추가·삭제·재작성한 말과 입력 간격의 변화처럼 확인된 사실을 구분한다.
동일 텍스트의 반복 수신은 새 의미 신호가 아니므로 의미 분석을 생략할 수 있다. 다만 시각·멈춤·재개 등 입력 상태 변화는 계속 관찰한다.
타이핑 패턴에 대한 숫자 임계값이나 진단 점수는 미정이다. 위의 최종 발화 감정 배점 1·2·3과 혼동하지 않는다.

### 3. 문맥 대조

추가·삭제·교체한 부분과 영향받는 앞뒤 문맥이 같은 사건을 가리키는지, 신중한 표현인지, 단순 오탈자 수정인지 본다. 유효한 이전 판단은 재사용하되 부정·주어·대상이 바뀌면 필요한 문맥까지 다시 살핀다.
감정 단어가 있어도 대상과 상황이 모호하면 정서 방향을 단정하지 않는다.
유저가 최종 문장에서 감정을 명시하면 그 **발화 내용**과 타이핑 패턴의 해석을 구별한다.

### 4. 쩜과 관계 데이터의 자리 확인

특정 사건·경험·관계에 속한 정서 맥락은 관련 쩜의 선택적 `context`에 간략히 반영할 후보가 될 수 있다.
감정만 독립적인 쩜으로 만들지 않는다. `jjtags`의 valence도 확인된 기억의 맥락에서만 다룬다.
말투·장기 정서 패턴 같은 상세 정보는 쩜과 다른 **관계 데이터**의 범위다.
상세 관계 기록·호스트별 갱신은 M4+ 연동과 규격에 의존한다. 지금 새 파일·필드를 정하지 않는다.

### 5. 최종 발화에서 재판단

입력 중에는 후보와 관찰 이유만 유지하며 확정 전 표현을 사건으로 저장하지 않는다.
최종 문장 전체를 최신 대화 맥락에 비춰 초안의 판단과 일치하는지 확인한다. 다르면 잠정 해석을 철회하거나 고치며, 늦게 끝난 이전 스냅샷의 분석이 최신 판단을 덮어쓰지 않게 한다.
개인적 사건은 [1계율](./1계율_쩜_추출_알고리즘.md), 기존 기억 정정은 [3계율](./3계율_기존_쩜_업데이트_알고리즘.md)로 넘긴다.
응답 태도에 도움이 될 때만 [7계율](./7계율_답변_가이드_생성_알고리즘.md)에 **불확실한 신호**로 전달한다.

| 관찰 | 판단 | 다음 처리 |
| --- | --- | --- |
| 오탈자만 고침 | 정서 변화 근거 없음 | 기록 후보 없이 종료 |
| 같은 사건을 여러 번 쓰고 지움 | 망설임 가능성 | 최종 문장과 맥락을 기다림 |
| 최종 문장에서 감정을 직접 말함 | 발화 내용 확인 | 관련 사건이 있으면 1·3계율 검토 |
| 사건 없이 “우울해”만 보냄 | 감정 단독 쩜 금지 | 7계율에 조심스러운 방향 후보 |
| 최종 발화가 앞선 초안을 부정함 | 초안 판단 철회 | 최종 발화 기준 재판단 |
| 개인정보가 입력 중 노출됨 | 이 계율로 보존 결정 금지 | [13계율](./13계율_개인정보_및_민감정보_처리_알고리즘.md) 우선 |

멈춤·재개에 따른 세션 상태는 [11계율](./11계율_세션_상태_관리_알고리즘.md)이 맡는다.

## 출력: 해마 판단 기록의 예

관찰한 변화, 가능한 해석, 불확실한 이유, 최종 발화 확인 여부, 관련 쩜 후보를 나누어 적는다.
이 예시는 `context`나 관계 데이터의 실제 직렬화 형식을 정하지 않는다.

> 관찰: “말할까 말까”를 지웠고 같은 사건을 다시 썼다.
> 해석: 표현을 고르는 중일 수 있으나 이유는 확인되지 않았다.
> 상태: 전송 전이므로 사실·감정 확정 보류.
> 전달: 최종 발화가 같은 사건을 유지하면 관련 쩜의 맥락과 답변 가이드를 재검토.

변화가 없거나 의미를 좁힐 근거가 없으면 “특별한 신호 없음” 또는 “판단 보류”가 정상 결과다.

## 가상 예시

### 예시 1 — 쓰다 지운 분노

초안: “그 사람 정말 화나” → 삭제 → 최종: “그 사람과 약속이 어긋났어.”
문장 변경만 확인된다. 최종 발화로 분노의 강도와 원인을 확정하지 않는다.
약속의 개인적 의미는 1계율에 묻고 가이드에는 단정 없는 조심스러움을 제안한다.

### 예시 2 — 느린 입력 뒤 기쁜 소식

긴 간격 뒤 최종: “드디어 합격했어!”
느린 입력을 불안으로 기록하지 않는다. 합격 소식은 사건 쩜 후보로 살핀다.
축하 방향은 7계율에 전달할 수 있으나 호스트의 실제 문장은 만들지 않는다.

### 예시 3 — 한국어 표기 수정

“성수 카페”를 “성수카페”로 고쳤다.
정서 변화 신호는 없다. 같은 장소의 별칭·정정 여부는 [2계율](./2계율_기존_쩜_탐색_알고리즘.md)로 넘긴다.
`그 카페에`처럼 조사가 붙거나 주어가 빠져도 새 감정 신호로 보지 않고 앞선 지시 대상을 확인한다.

### 예시 4 — 감정만 말한 경우

최종: “오늘 좀 우울해.”
유저가 우울하다고 **말한 사실**과 장기 기억으로 남길 사건은 다르다.
“우울” 쩜은 만들지 않는다. 호스트에 조심스러운 방향만 제안한다.

### 예시 5 — 스냅샷 누락

첫 입력 뒤 중간 스냅샷이 유실되고 최종 문장만 도착했다.
타이핑 속도·망설임 추이는 알 수 없다. 최종 문장과 기존 대화만으로 판단한다.
최종 문장이 “됐어요 ㅎㅎ”여도 만족·체념·대화 종료 중 무엇인지 추가 맥락 없이는 정하지 않는다.

## 보류·실패 처리

- 최종 발화가 없으면 기억 갱신 여부를 보류한다.
- 시간 정보가 없거나 순서가 뒤틀리면 속도·간격 비교를 건너뛴다.
- 기존 쩜과 사건의 연결이 불분명하면 `context` 반영을 보류한다.
- 신호와 최종 발화가 충돌하면 신호의 해석을 철회한다.
- 사생활을 침범할 수 있는 정밀 정보는 [13계율](./13계율_개인정보_및_민감정보_처리_알고리즘.md)을 먼저 따른다.
- 탐지가 실패해도 최종 발화의 일반적인 추출·회상 흐름은 막지 않는다.

- 입력 중 관찰과 최종 유저 발언이 명확히 구분되는가?
- 멈춤·삭제·느린 입력만으로 특정 감정을 확정하지 않는가?
- 감정 자체를 독립 쩜으로 생성하지 않는가?
- 관련 쩜의 간략한 `context`와 별도 관계 데이터의 역할을 혼동하지 않는가?
- 보류 결과가 자연스럽고, 호스트에 직접 말을 걸지 않는가?
- `meta`를 읽어 서비스별 분기를 만들지 않는가?
