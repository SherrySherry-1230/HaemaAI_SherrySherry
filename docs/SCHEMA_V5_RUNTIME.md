# 해마.ai v5 저장·계산 연결

[구조 명세](SCHEMA.md)의 v5 계약을 별도 SDK 경로로 제공한다. 기존 콘솔과 대화 추출은 v4 경로를 유지한다. 개인 기억의 자동 변환이나 운영 서버의 v5 전환을 수행하지 않는다.

## 저장과 검토

`FileJJumV5Store({memoryRoot, typeRequirements, maskedName})`는 `read/list/save`를 제공한다. 신규 저장에는 `createOnly:true`, 갱신에는 읽은 결과의 `expectedEtag`를 전달한다. 갱신에서 생략한 최상위 선택 키는 CAS로 확인한 현재 원본에서 보존한 뒤 공통·타입별·조건부 검사를 수행한다. 공통 필수 키는 매 요청에 필요하며 기존 값으로 보충하지 않는다. 기존 ID·최초 출처·근거·이력은 보존한다.

공급한 객체·목록은 완성된 해당 값으로 검사하며 내부를 자동 병합하지 않는다. `meta` 내부도 해석하지 않는다. `0`·`false`는 실제 제공값으로 유지하며, SDK 갱신의 선택 `undefined`는 JSON의 키 생략과 동일하게 처리한다. 생략이나 후보의 빈값 정규화는 삭제 명령이 아니며, 이 경로에 선택 필드 삭제 API는 없다. 직접 저장의 `null`·빈 배열·빈 객체는 검증 오류다. 기존 이력·근거 보호와 동시 변경 거절은 갱신에도 적용한다.

`saveJJumV5Candidate({repository,input,typeRequirements,save,reviewer})`는 선택 빈값 정리, 기존 최상위 선택값 보존, 공통·타입별 필수 검사, 저장, Laya 검토를 연결한다. 타입별 정책은 실제 확정 기준을 호출자가 제공해야 한다. 누락이나 정책 대기는 `needs_information`으로 반환하고 AI가 사실을 보충하지 않는다. 검토 전·실패는 정상 판정이 아니다. `retryReview:true`는 대기·실패 검토를 명시적으로 재개한다. 늦게 끝난 검토는 저장 당시 값과 일치할 때만 적용한다.

`assessV5MemoryAccess`와 `buildV5HostMemory`는 공개 범위와 실제 인지 근거를 각각 판단한다. 호출 서비스가 대상의 인증·사용자 범위를 확인해야 한다. 전체 공개는 호스트 인지나 지금 직접 언급할 권한을 생성하지 않는다.

## 계산과 변경 이력

`LocalCalculationProfileProvider({entryPoints})`에 개인 프로필 경로를 명시한다. 계수 원문은 저장소 코드에 복제하지 않는다. 프로필 ID·버전·CSV 일치·체크섬을 검증한다. 로그/루트 선택, 복수 타입 결합, 미정 감쇠 단계 등은 확정된 정책이 없으면 `pending`이다.

`calculateJJumPower`는 네 기여값에 각각 0.23/0.17/0.29/0.31 하한을 적용하여 소수 원값을 합산한다. 음수·비정상 수치를 하한으로 숨기지 않는다. `formatJJumPower`의 한 자리 반올림 문자열은 표시용이다. 저장에 다시 사용하지 않는다.

`updateMentionSuitability`는 외부 평가 정책과 근거 ID에 따른 값 또는 증감을 적용하고 전후 이력을 기록한다. 기본 평가식이나 미평가 0점은 만들지 않는다.

`activateCalculationProfile`에는 `ownerId`, `selection`, `operationId`, `provider`, `repository`, `journal`, `evaluator`를 제공한다. 기존 동일 사용자·프로필의 v5 쩜 전체를 찾아 보존된 근거로 재계산한다. `evaluator`가 원점수에서 최종 기여값으로 바꾸는 확정 정책을 제공한다. 없는 정책은 보류하며 기존 파워를 보존한다.

`FileProfileRecalculationJournal({root})`는 목표 버전과 마지막 완료 버전을 구분한다. 쩜별 저장과 재시도는 지원하지만 여러 쩜 전체를 한 번에 원자적으로 바꾸지는 않는다. 동시 변경·근거 부족·실패는 개별 결과에 남기며 미완료 전환을 완료로 기록하지 않는다. 중단으로 남은 잠금은 다른 프로세스의 실행 여부를 확인한 뒤 관리해야 한다.

`applySeonEvidenceV5`는 확정 계산 결과를 양쪽 쩜에 적용하는 순수 함수다. 일반·부모자식 공유값과 상위하위 수신값, 정정 근거, 재전송을 구분한다. 양쪽 파일의 원자 저장은 별도 저장 계층에서 구현해야 한다.

## 적용 경계

- 실제 타입별 필수 항목 목록과 최종 기여 환산식·매너 가감 기준은 주입하는 정책이다. 이 모듈이 새 기준을 정하지 않는다.
- v5는 별도 시험 저장소에서 사용한다. v4 어댑터가 v5를 발견하면 축소 저장을 막기 위해 오류를 반환한다. 운영 쩜통에 혼용하여 기존 v4 서버를 전환하지 않는다.
- v4→v5 이행에는 없는 과거 호스트·점수·발화 정보를 추측하지 않는 별도 변환 계획이 필요하다.
- 쩜선 양쪽 저장, 전체 호스트 권한 관리, 실제 AI 추출의 v5 전환은 이 SDK 준비와 별도 작업이다.
- 로컬 합성 테스트 파일은 기존 Git 제외 규칙을 따른다. 기록된 로컬 결과를 깨끗한 checkout의 자동 검사로 간주하지 않는다.
