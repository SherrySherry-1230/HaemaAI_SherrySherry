# 쩜(JJum) 스키마 (v5 기획안)
> v5는 미구현 기획안이다. 현재 구현·파일 검증의 기준은 v4이며, 아래 v5 항목은 저장 구조 확정이나 마이그레이션 완료를 뜻하지 않는다.
> 회상 점수 경계·쩜파워·언급 적절성·이름 원칙은 기획팀이 합의한 기준이고, 계산식·계수·저장 방식은 검증 전 제안이다.
  > 해마태그 H-tag -> 쩜태그 JJ-tag로 교체
> 확정: 2026-09-22 (기획팀) · 용어 전면 교체: 2026-09-13. 원문 출처: 마이풉 기획서 §2-1-1 "해마.AI".
> '해마세포' 구용어 -> '쩜' 으로 교체 'HCell'도 'JJum'으로 일단 교체
> v4의 구현 기준은 TypeScript 타입 `src/types/jjum.ts`를 확인한다. 이 문서의 v5 제안을 현재 코드와 동일시하지 않는다.
> 원칙: `meta`는 서비스별 자유 확장 소켓이며 **Haema는 그 내용을 해석하지 않는다** (도메인 무지).

> **생각과 기억의 최소단위, 생각점·기억점, 그래서 점이다!**
> — 쩜(jjum)은 해마(Haema)의 기본 단위. 쩜이 이어지면 쩜선(Seon)이 된다.
> - 쩜은 보존하지만, 쩜선의 활성도/가중치는 감쇠할 수 있다.

## 용어
| 개념 | 문서 용어 | 코드 및 경로 |
| :--- | :--- | :--- |
| **기억의 최소 단위**<br>• AI와 유저가 공유하는 기억 하나<br>• '기억점'의 '점' ➔ 일상 단어와 구분하기 위해 '**쩜**'으로 명명 | **쩜**<br>*(구: 해마세포, 해마쎌)* | • 타입: `JJum` (`jjum`)<br>• 논리 경로: `jjums/{jjumId}`<br>• 파일 어댑터 실제 경로:<br>`{storageRoot}/🧠장기기억저장소_feat.해마🧠/🪣쩜통🪣/{jjumName}.jj`<br>•기존 baseDir 기반 저장 구조는 폐기하고, 사용자가 선택한 storageRoot 기반으로 쩜통 경로를 잡아라.|
| **연상 네트워크**<br>• "점이 연결되면 선" | **쩜선** | • 타입: `Seon`<br>• 필드명: `seons` |
| **쩜에 달린 표식**<br>• 정서가(Valence: 긍정/중립/부정) 등 포함 | **JJ-tag** *(쩜태그)* | • 필드명: `jjtags` |

- "노드"·"엔티티"·"마디"는 쓰지 않는다.
- 'Jj'표기는 해마.ai 세계관에서 불법이다. 쩜의 영문 JJum에 들어가는 표기는 반드시 'jj','JJ'로 표기한다.
- 문서상 용어는 JJum, 코드 식별자는 기존 camelCase 규칙에 따라 jjumId, jjumName을 사용한다.

```
쩜 스키마 — 논리 경로 jjums/{jjumId} (현재 v4 파일 어댑터 경로와 v5 이름 원칙은 아래에서 구분)

**문서 하단에 파일명(쩜 파일) 규칙 필독**
해마 콘솔에 노출되는 쩜의 정보 ✅표시(요약쩜에 표시, 길면 ‘...’활용해서 표시)  ➕는 점을 펼쳤을때만 드러남

// ═══ 신원 ═══
jjumId          string      // 자동 생성되는 쩜의 고유 ID.
                            // 유저는 몰라도 되므로, 노출시키지 않는것을 원칙으로 한다. 쩜의 파일명이나 사용자 입력값을 ID로 사용하지 않는다.
✅jjumName        string      // 사용자의 일상 표현을 대표 이름으로 삼는다 ("아빠", "핑크", "까페").
                            // v5 제안: 파일명도 이 표현을 우선한다. jjumId는 이름 변경에도 고정한다.
✅aliases         string[]    // 별칭 (["핑크", "홍길동"]) — 어느 이름으로 언급돼도 같은 쩜 히트
✅type            string      // 개방형. AI가 자유 생성 (인물·장소·사물·사건·개념·작품·조직·표현·시기 …)
✅jjtags          string[]    // JJ-tag — 다중 분류 ("댕춍코인" = [코인, 사건, 밈]). valence(긍정/중립/부정)도 JJ-tag

// ═══ 내용 ═══
✅summary         string      // 쩜 한 줄 요약 ("월 1~2회 만나는 친한 친구") — 배치가 생성·갱신
➕facts           array       // [{ text, addedAt, source }]  ➕source: conversation | user_edit | batch
➕events          array       // [{ date, summary, refJJumIds[] }] — 사건에 함께 등장한 쩜 연결
 // ═══ 맥락 ═══
✅context         object?     // 기억이 형성된 대화·환경 맥락. 급작스런 타이핑 속도 변화와 함께 꼼꼼히. 현단계에선 느껴지는 사용자의 감정도 여기에 간략기록 ('관계 데이터' 폴더에 따로 분리 자세히 기록. 마일스톤4 이후에 감정 따로 분리)

// ═══ 쩜선 — 연상 네트워크 (핵심) ═══
✅seons           array       // [{ targetId, weight, label?, lastActivated }]
                            //   weight: 함께 언급될수록↑, 미사용 시 서서히 감쇠
                            //   label: 관계 설명(선택) — "창작자", "동일 사건"
                            //   회상&연상 규칙: MCTS, weight 따라 탐색 / weight 상위 N개 / 총 토큰 상한
                            //   중복 규칙(2026-09-06, "핀 여러 개"): 같은 상대라도 라벨이 다르면 쩜선 여러 개 허용
                            //     (예: "이전 동거" + "이사 원인"). 라벨이 같은 쩜선이 또 오면 새로 만들지 않고 기존 weight↑.
                            //     회상 점수는 같은 상대로 가는 쩜선 중 가장 굵은 것 기준.

// ═══ 통계 ═══
➕mentionCount    number      // 언급 횟수 — 인기순 정렬 키
➕firstSeen       timestamp
➕lastMentioned   timestamp   // 날짜순 정렬 키, 최근 언급 시각 — 회상 및 관리 우선순위 계산에 활용
➕recallCount     number      // AI가 회상에 실제 사용한 횟수. recallCount === 0 이면 미회상쩜 -> 알고리즘에서 보너스 줄 예정.
➕lastRecalled    timestamp?  // 마지막으로 회상된 시각

// ═══ v5 기획 축: 현재 v4 필드가 아님 ═══
jjumPower        positive integer // 지속 점수, 양의 정수이며 상한 없음. 사용자 삶에 미친 영향의 크기; 긍정·부정 모두 가능
mentionSuitability integer -10..+10 // 직접 언급 적절성의 저장 기본값. -10 매우 꺼림, +10 반복 언급해도 좋음
// 회상 점수 R은 저장 필드가 아니다. 턴마다 계산하고 사라지는 0..5 정밀값이다.
// 콘솔은 등급 판정을 원값 R로 한 뒤 소수 둘째 자리 이하는 버려 소수 한 자리로 표시한다. 단, 0<R<0.1은 0.1로 표시하고, R=5일 때만 5.0으로 표시한다. 5 미만 값(예: 4.99)은 5.0으로 반올림하지 않는다.
// 현재 맥락·명시 선호에 따른 언급 적절성의 턴별 판단은 저장 기본값과 별개다.
// v5 필드의 실제 이름·저장 위치·이행 방식은 미정이며 위 표기는 기획상 구분을 위한 이름이다.

// ═══ 관리 ═══
pinned          boolean     // 자동 정리 영구 면제
status          enum        // active | resting | merged
                            //   resting: 당장 회상하지 않는 기억. 데이터는 영구 보존
                            //   merged:   다른 쩜에 흡수됨
mergedFrom      string[]    // 흡수한 구 쩜 ID들 — 오병합 분리 복원용
mergedInto      string?     // (status=merged일 때) 흡수된 대상 역참조
editHistory     array       // [{ date, action, field, by }]  by: user | ai | batch

// ═══ 확장 소켓 ═══
meta            map         // 서비스별 자유 확장. Haema는 내용을 해석하지 않는다 (도메인 무지)

// ═══ 피드백 ═══
responseFeedback[] array      // 호스트 AI 답변에 대한 유저 반응 및 평가(쩜에선 간략 기록. 자세히는 별도 '관계 데이터'폴더 아래 파일로)
                            //[{ timestamp, result, cues, responseId? }]  

// ═══ 소속 ═══
➕ownerId         string      // 기억의 주인. 인증 방식은 Haema 소관 아님 — 문자열로 받을 뿐
➕sourceService   string      // "mypoopai" | "daengchong" | …
schemaVersion   number      // 마이그레이션 대비
```

## 회상 점수 R의 현재 분류

| R 범위 | 분류 | 처리 의미 |
| --- | --- | --- |
| `0` | 관련 없는 쩜 | 현재 대화와 관련이 없어 호스트에게 전달하지 않는다. |
| `0 < R < 1` | 후보 쩜 | 약한 관련 가능성만 있어 검토 후보로 남긴다. |
| `1 ≤ R < 3` | 관련 쩜 | 현재 대화와 관련된 쩜이다. |
| `3 ≤ R < 5` | 강력 추천 쩜 | 연상·맥락상 매우 중요하여 강하게 추천한다. |
| `R = 5` | 확정 쩜 | 사용자가 현재 발화에서 직접 언급한 쩜이다. |

이 분류는 턴별 회상 관련성만 나타낸다. `jjumPower` 같은 지속 점수나 다른 우선순위 값과 혼동하거나 대신하지 않는다.

콘솔은 등급을 원값 R로 먼저 판정한 뒤 소수 둘째 자리 이하는 버려 소수 한 자리로 표시한다. 단, `0 < R < 0.1`은 관련 없는 쩜으로 보이지 않도록 `0.1`로 표시하고, `R = 5`일 때만 `5.0`이다. 따라서 `R = 0.99`는 `0.9`, `R = 2.99`는 `2.9`, `R = 4.99`는 `4.9`로 표시한다.

## 쩜 이름 및 파일명 보호 규칙
  - 쩜들의 파일명은 사람과 AI가 알아보기 쉽도록 {{jjumName}}.jj(jj는 쩜만의 독특한 확장자 시스템)으로 하되, 다음 maskedJJumName 예외사항이 있다.
  - 쩜 내부의 jjumName은 상관없으나 사람 실명, 특정 상품이나, 브랜드가 파일명으로 노출 되면, 로컬에서 사람 혼자 보더라도 부담스러울 수 있다. 다음처럼 '파일명'일 경우만 마스킹한다.

### maskedJJumName
#### 한글 고유명칭 마스킹
    - 한글 고유명칭은 **영문 대문자 O**를 마스킹 문자로 사용한다.
    - 짧은 이름은 1글자 정도를 남기고 나머지를 O로 치환한다.
    - 긴 이름은 앞·중간·뒤의 형태를 일부 남기고 식별 가능한 핵심 부분을 O로 치환한다.
    - 여러 단어로 이루어진 명칭은 각 단어의 형태를 가능한 한 유지한다.
    - 마스킹의 목적은 내용을 없애는 것이 아니라 파일명에서만 부담을 줄이는 것
    ```
      예시 :
      홍길동 → 홍O동, 김구 → 김O, 스타벅스 돌체라떼 → 스O벅O 돌O라떼, 볼더스콘 카페 → 볼O스O 카페
      파일명은 홍O동.jj 하지만 파일 내부는 jjumName = 홍길동
    ```
#### 욕설·비속어 마스킹
  - 욕설이나 비속어가 쩜 이름으로 생성되는 경우에도 마스킹한다.
  - 욕설 자체를 파일명으로 그대로 노출하지 않는다.
      ```
      예:
      씨발롬
      → O빌O
        파일명은 O빌O.jj 하지만 파일 내부는 jjumName = 씨발롬
      ```

  - 욕설의 경우 일반적인 고유명칭보다 강하게 마스킹할 수 있다.
  - 단, 쩜의 세부 내용(facts, events, summary)까지 불필요하게 삭제하거나 변형하지 않는다.

#### 영문 고유명칭 마스

  - 영문 고유명칭은 **한글 ㅇ**을 마스킹 문자로 사용한다.


## 원칙
- 쩜 하나당 .jj 파일 하나를 사용한다.
- 파일명에는 마스킹된 jjumName을 사용한다.
- _index.jj는 이름·별칭과 jjumId를 연결하는 인덱스다.
- 인덱스가 유실되거나 불일치하면 파일 스캔으로 복구할 수 있어야 한다.
- 사용자가 손으로 수정한 .jj 파일도 반드시 v4 스키마 검증 후 로드한다.
- 깨진 파일 하나 때문에 전체 Haema가 중단되어서는 안 된다.
- 개인 쩜 데이터는 개발 저장소에 무단 커밋되지 않도록 별도로 보호한다.

### 쩜 기록 시 표현·오탈자 처리 원칙

- 사용자의 오탈자는 의미가 명확한 경우 가능한 한 교정하여 쩜에 기록한다.
- 오탈자를 교정하더라도 사용자가 실제로 사용한 원문을 임의로 다른 의미로 바꾸지 않는다.
- 사용자의 고유한 말투·표현 습관은 쩜의 내용에서 임의로 표준화하지 않으며, 필요한 경우 별도 **관계 데이터**의 말투 정보에 반영한다.
- 신조어·개인적 표현·의미가 불명확한 단어는 일반적인 사전적 의미로 임의 해석하지 않는다. (한국은 신조어가 자주, 많이 나오는 문화적 특징이 있다...)
- 해당 표현이 쩜 생성이나 회상에 중요하고 의미를 확정하기 어려운 경우, 호스트 AI를 통해 사용자에게 의미를 확인할 수 있다.
- 예: 사용자가 `"샤갈!"`이라고 표현하였을 때 이를 화가 **샤갈**로 자동 해석하지 말고, 사용자의 개인적 표현인지 확인할 수 있다.

## 사용자·호스트 기본 쩜의 생명주기 (v5 기획)

- **사용자 본인 쩜과 실제 대화 상대인 호스트 챗봇 쩜을 함께 생성·연결한다.** 가입 시 호스트가 확정된 서비스는 계정 생성 시, 여러 캐릭터 중 선택하는 서비스는 선택 완료 후 해당 대화창에 처음 들어갈 때 초기화한다. 첫 발화나 쩜 추출을 기다리지 않으며, 선택 전 사용자 본인 쩜만 따로 생성하지 않는다.
- 같은 사용자 계정에는 하나의 사용자 본인 쩜을 연결한다. 로그인·세션 변경·초기화 재시도에는 기존 `jjumId`를 재사용한다. 다른 캐릭터의 대화창에 처음 들어가면 사용자 본인 쩜은 유지하고 해당 호스트 쩜만 추가한다. 이전 캐릭터로 돌아오면 그 호스트 쩜도 재사용한다.
- 계정 및 호스트와 쩜을 연결하는 고유 식별 정보와 발화자별 지칭 기준이 필요하다. 표시 이름이나 무조건적인 대명사 별칭 매칭으로 대상을 판정하지 않는다. 이 정보의 실제 필드명·저장 위치는 미정이며, 코어가 `meta`를 해석하도록 우회하지 않는다.
- 일반 쩜과 두 자아쩜(사용자 본인 쩜·호스트 쩜)은 모두 `mentionCount=1`, `recallCount=0`으로 시작한다. 일반 쩜은 사용자의 첫 언급으로, 두 자아쩜은 대화 시작 전 생성 자체를 최초 1회 언급으로 취급하여 초기화한다. 자아쩜의 `lastMentioned`는 생성 시각으로 기록하되 실제 대화 발화를 만들어 기록하지 않는다. 초기 1회는 각 쩜의 최초 생성에만 부여하며, 이후 사용자가 해당 자아쩜을 처음 실제로 언급하면 `mentionCount=2`가 된다. 재사용·로그인·새 세션·캐릭터 전환·재진입·초기화 재시도에서는 기존 횟수를 보존하고 추가 집계하지 않는다. 생성 시각 자체는 파워의 노출 기간이나 감정 총량을 뜻하지 않는다.
- 현재 v4의 `createJJum()`은 `mentionCount=1`, `lastMentioned=생성 시각`, `recallCount=0`으로 초기화하므로 이번 초기값 결정과 일치한다. 생성 출처·식별 정보·동시 초기화 경로는 구현 전에 정하며, 이 문서 변경으로 계정 연동 코드나 기존 파일이 이행된 것은 아니다.
- 초기 파워 값, 타입 목록, 계수 및 저장 필드는 별도 파워·스키마 설계에서 정한다. 상세 처리 순서는 [최신 기획서의 전체 파이프라인](해마.ai_최신기획서.md)을 따른다.
