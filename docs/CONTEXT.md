# CONTEXT.md — 배경지식 (참고용, 코드 반영 금지)

이 문서는 Haema를 왜 만들고 어디서 검증하는지에 대한 배경지식이다.
**여기 나오는 어떤 도메인 개념(배변·캐릭터·건강 등)도 Haema 코드에 등장해선 안 된다.**
(→ CLAUDE.md의 "도메인 무지 원칙")
  
## 첫 테스트 베드: 마이풉 (MyPoop)

- 위치: 형제 폴더 `../MyPoop_SherrySherry`
- AI 고양이 캐릭터 **피피·푸푸**가 유저와 1:1 채팅하며 배변·배뇨 건강 기록을 만드는 반응형 웹앱(PWA).
- 마이풉 쪽은 원래 `src/lib/memory.ts`에 Haema 인터페이스 타입 + 목(mock)만 두고
  추후 `@haema/core`를 설치해 교체하는 구조이나,
  현재 마이풉에는 `src/lib/memory.ts`가 존재하지 않으며 목 구현도 아직 시작하지 않았다.
  이는 의도된 상태로, 마이풉↔Haema 연동 코드는 아직 착수하지 않았다.
  연동은 마이풉에 직접 붙이기 전에 임시 웹콘솔(로컬 HTML)로 먼저 대표님과 기획자가 돌려보고,
  그 다음에 정식 연동하는 순서로 진행한다.

## Haema가 검증할 목표

목표 수준의 예:

> 유저: "어제 핑크랑 술먹고 피똥샀네"
> (다음 달 비슷한 상황에서) AI: "지난달에도 핑크랑 마셨는데 또?ㅋㅋ"

이런 **자발적 회상**이 자연스럽게 나오는가. 3대 검증 요소:

1. **점 자동 생성** — 대화에서 "핑크" 같은 대상을 스스로 점(JJum)으로 추출·저장하고 H-tag를 붙이는가.
2. **관계 추론** — 반복 언급으로부터 "월 1~2회 보는 친한 친구" 같은 관계 특성을 축적하는가.
3. **꺼낼 타이밍 판단** — 관련 있을 때만 꺼내고, **안 꺼내야 할 때는 침묵**하는가.
   (기억이 있다고 매번 언급하면 오히려 실패)

## 장기 비전

- 마이풉에서 검증 후, 후속 프로젝트(댕춍이, AI 친구 서비스 등)의 **기억 엔진**이 된다.
- 그래서 처음부터 범용 모듈로 설계한다 — 특정 서비스에 붙는 코드가 아니라,
  어떤 LLM 서비스든 이식할 수 있는 인공 해마.
