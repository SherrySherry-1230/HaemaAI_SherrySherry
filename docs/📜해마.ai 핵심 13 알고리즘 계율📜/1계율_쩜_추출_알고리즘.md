# 1계율 — 쩜 단위 추출 알고리즘

> **목적:** 사전적 의미가 아니라, 대화하는 인간에게 실제로 의미가 있는 기억 후보를 찾는다.
> **문서 상태:** 기획 명세. 이 문서가 작성되었다고 기능의 구현이 완료된 것은 아니다.
> **찾을 말:** 쩜 추출, 개인적 의미, 기억 후보, 일상어, 신조어, 중복 언급, 여러 기억.
> **진입 안내:** [상황별 읽기 목록](README.md). 이 단계는 후보를 만들며, 저장 여부는 후속 계율에서 결정한다.

## 1. 언제 이 문서를 읽는가

- 새로운 사용자 발화를 받았거나, 입력 중인 문장이 의미 있게 달라졌다.
- 일상적인 표현을 기억해야 할지, 개인적인 경험으로 보아야 할지 판단해야 한다.
- 한 문장에 사람·장소·사건·선호가 함께 나와 기억 단위를 나눠야 한다.
- 새로운 이름이나 신조어를 만났지만 사용자에게 어떤 의미인지 아직 모른다.

이미 저장된 쩜의 동일성을 판단하려면 [2계율](2계율_기존_쩜_탐색_알고리즘.md), 사실을 고치려면 [12계율](12계율_쩜_충돌_및_정보_갱신_알고리즘.md)을 읽는다.
이 문서만 읽고 신규 쩜을 저장하거나 두 쩜을 병합하지 않는다.

## 2. 필요한 정보

| 정보 | 사용하는 이유 | 없을 때 |
| --- | --- | --- |
| 현재 발화 또는 입력 스냅샷 | 후보와 근거를 찾는다. 스냅샷은 입력 중 문장의 한 시점이다. | 빈 입력이면 후보 없음으로 끝낸다. |
| 입력 중인지, 전송된 최종 발화인지 | 아직 바뀔 문장과 사용자가 보낸 말을 구분한다. | 확정 여부를 확인할 때까지 잠정 후보로 둔다. |
| 사용자·세션 식별 정보와 시각 | 다른 사람의 기억, 이전 입력과 뒤섞이지 않게 한다. | 후보 저장과 사용자별 탐색을 보류한다. |
| 필요한 이전 대화 | “그 사람”, “거기”, 인용, 정정의 대상을 확인한다. | 대상을 지어내지 않고 보류한다. |
| 허용된 관계 정보와 호스트의 맥락 | 개인적 표현과 대화 상황을 이해한다. | 없는 배경을 추측으로 채우지 않는다. |

이미 저장된 쩜 전체를 읽어야 추출할 수 있는 것은 아니다. 후보를 만든 뒤 2계율에서 필요한 기억을 찾는다.
`meta`는 서비스가 맡긴 확장 데이터다. 해마가 그 내용을 해석해 후보를 만들거나 분류하지 않는다.

## 3. 추출할 가치가 있는 정보

판단의 중심은 **“이 정보를 다시 기억하면 이 인간의 경험과 관계를 이해하는 데 도움이 되는가?”**이다.
아래 분류는 판단을 돕는 예시이며 `type`의 고정 목록이 아니다.

| 의미 | 발화 예시 | 기억할 부분 |
| --- | --- | --- |
| 사실 | “나는 부산에 살아.” | 사용자와 관련된 거주 사실 |
| 선호 | “매운 음식은 별로 안 좋아해.” | 개인의 비선호 |
| 경험 | “작년에 제주도를 혼자 여행했어.” | 시기와 경험의 맥락 |
| 관계 | “핑크는 고등학교 때부터 친구야.” | 핑크와 사용자의 관계 |
| 사건 | “면접에서 떨어진 날 그 카페에 있었어.” | 사건과 장소의 연결 |
| 습관 | “자기 전에 항상 음악을 들어.” | 반복하는 개인적 행동 |
| 개인적 표현 | “그곳을 도망 카페라고 불러.” | 특별한 별칭과 그 의미 |
| 관심사 | “요즘 인디게임 개발에 빠져 있어.” | 현재 이어지는 관심 |

감정이 경험의 의미를 설명하면 관련 쩜의 `context`와 쩜태그에 필요한 범위를 반영할 수 있다.
그러나 “슬프다”, “기쁘다”라는 말만으로 감정 자체를 독립 쩜으로 만들지 않는다.
상세 감정·말투·반응의 관계 데이터는 [5계율](5계율_감정_감지_알고리즘_임시.md)의 경계에 따르고, 별도 감정 저장 구조를 이 문서에서 새로 확정하지 않는다.

## 4. 판단 순서

### 4.1 발화의 성격과 범위를 먼저 확인한다

1. 실제 사용자 경험인지, 질문·인용·가정·농담·호스트의 추측인지 확인한다.
2. 누가 겪은 일인지와 어느 시기의 이야기인지 확인한다.
3. 개인정보나 민감정보가 있으면 [13계율](13계율_개인정보_및_민감정보_처리_알고리즘.md)의 기준을 적용한다.
4. 아직 입력 중이라면 나중에 지워지거나 반대로 바뀔 수 있는 잠정 후보로 다룬다.

“제주도에 가고 싶다”를 “제주도에 다녀왔다”로 기록하지 않는다.
“친구가 부산에 산대”를 사용자의 거주 사실로 바꾸지 않는다.

### 4.2 개인적 의미를 판단한다

- 사용자 개인의 사실·선호·경험·관계·사건·습관 등을 설명하는가?
- 나중에 다시 이해하거나 회상할 가치가 있는가?
- 다른 기억과 연결했을 때 개인적 맥락이 더 분명해지는가?
- 개인적 맥락을 빼면 누구에게나 같은 사전적 의미만 남는가?

마지막 경우에는 제외한다. 개인적 의미가 불명확하면 보류한다.
중요도 숫자나 생성 임계값은 원문에 확정되어 있지 않으므로 임의로 붙이지 않는다.

### 4.3 기억 후보와 세부 사실을 구분한다

한 발화에서 여러 후보를 찾을 수 있지만, 모든 명사와 모든 속성을 별도 쩜으로 늘리지 않는다.

예: “핑크랑 성수 카페에서 면접 떨어진 날 이야기를 했어. 그 뒤로 그 카페가 불편해.”

- `핑크`: 인물·관계 후보.
- `성수 카페`: 장소 후보.
- `면접 떨어진 날`: 사건 후보.
- `성수 카페에 대한 비선호`: 장소·사건의 사실 또는 맥락으로 붙일 내용인지 검토한다.

독립적으로 기억할 이유가 있을 때만 별도 후보로 유지한다.
관련 쩜끼리 연결할 근거는 함께 넘기되, 실제 `jjumId`가 없는 대상을 향한 쩜선을 만들지 않는다.

### 4.4 사용자 표현의 뜻을 보존한다

명확한 오탈자는 바로잡을 수 있지만 의미가 달라지면 안 된다.
고유한 말투는 억지로 표준화하지 않는다. 신조어와 개인적 표현을 사전적 의미로 단정하지 않는다.

한국을 우선 타깃으로 하므로 한국어 원문에서 판단한다. 필요한 한글 이름과 표현을 영문 번역이나 로마자로 대체하지 않는다.
“핑크랑”, “핑크에게”의 조사는 문맥을 통해 구분하되, 이름 끝 글자를 무조건 잘라내지 않는다.
주어가 생략된 “또 늦었네”는 누가 늦었는지 근거가 없으면 보류한다.
`ㅋㅋ`·`ㅎㅎ`·`ㅠㅠ`와 존댓말·반말은 표현 단서이며, 그 자체로 감정이나 친밀도를 확정하지 않는다.

예: “샤갈!”은 문맥 확인 없이 특정 화가를 뜻하는 쩜으로 만들지 않는다.
기억에 중요한 표현인데 의미를 모르면 확인할 질문 후보를 [7계율](7계율_답변_가이드_생성_알고리즘.md)로 넘긴다.
해마가 사용자에게 직접 질문하지는 않는다.

### 4.5 기존 기억과의 관계를 확인하도록 넘긴다

후보를 [2계율](2계율_기존_쩜_탐색_알고리즘.md)로 보낸다. 정확한 이름·별칭은 강한 탐색 단서지만 동일 대상이라는 최종 증거는 아니다.
문맥·대상·사용자의 명시적 동일/상이 설명을 함께 확인한다.

- 동일한 대상이고 새 정보가 있다면 [3계율](3계율_기존_쩜_업데이트_알고리즘.md)에서 갱신한다.
- 별개 대상이라는 근거가 충분하면 [4계율](4계율_신규_쩜_생성_알고리즘.md)에서 생성한다.
- 동명이인·애매한 별칭·모순이 있으면 [12계율](12계율_쩜_충돌_및_정보_갱신_알고리즘.md)에서 정리한다.
- 단순 반복이면 새 쩜을 만들지 않는다. 언급 통계의 반영은 3계율에 맡긴다.

### 4.6 최종 발화에서 다시 검토한다

입력 중 후보는 최종 발화와 대조해 유지·수정·철회를 결정한다.
예를 들어 “그 카페 싫어…”가 “싫어하는 줄 알았는데 좋아졌어”로 바뀌면 앞부분만 확정 사실로 남기지 않는다.
같은 발화의 여러 스냅샷을 여러 번의 독립 언급으로 세지 않는다.

기획서는 실시간 처리와 최종 저장을 모두 요구한다.
중간 결과를 디스크에 언제·어떻게 기록할지는 미확정이며, 자세한 상태 관리는 [11계율](11계율_세션_상태_관리_알고리즘.md)을 따른다.

## 5. 제외·보류·실패를 구분한다

| 상황 | 판단 | 후속 처리 |
| --- | --- | --- |
| “퇴근했어”, “밥 먹었어”, “오늘 비가 와”만 있음 | 개인적 의미가 없으면 후보 없음 | 정상 종료 |
| “퇴근 후 늘 한강을 걸으면 마음이 편해져” | 장소·습관·개인적 의미가 있음 | 후보를 2계율로 전달 |
| 일회성 잡음·의미 없는 반복 | 제외 | 쩜을 억지로 만들지 않음 |
| “그 사람이 또 그랬어”인데 대상 불명 | 보류 | 필요한 맥락이나 질문 후보 정리 |
| 일반 감정 단독 표현 | 독립 쩜 후보 없음 | 필요한 신호만 5계율로 전달 |
| 추출 모델 오류·잘린 응답 | 처리 실패 | 후보 없음과 구별하고 기존 기억 보존 |
| 개인정보 처리 범위를 판단할 수 없음 | 해당 후보 보류 | 13계율로 전달 |

**빈 결과는 정상이다.** 추출 실패를 빈 성공으로 위장하지 않으며, 실패를 메우려고 기억을 지어내지 않는다.

## 6. 넘길 결과

출력은 신규 생성이 확정된 쩜 목록이 아니라 **기존 쩜 갱신 가능성을 포함한 추출 후보 목록**이다.
후속 판단에는 후보, 발화의 근거 부분, 입력 확정 여부, 불확실한 부분, 다음 처리 대상을 함께 전달한다.
불필요한 원문 전체나 민감정보를 판단 기록에 복제하지 않는다.

아래는 후보 내용의 설명용 예시다. 실제 API 계약이나 완성된 v4 저장 레코드를 뜻하지 않는다.

```json
{
  "candidates": [
    {
      "jjumName": "핑크",
      "type": "인물",
      "aliases": [],
      "jjtags": ["친구", "고교"],
      "summary": "고등학교 때부터 알고 지낸 친구",
      "facts": [
        {
          "text": "사용자는 핑크를 고등학교 때부터 친구라고 설명했다.",
          "source": "conversation"
        }
      ]
    }
  ]
}
```

후보가 없으면 `{"candidates":[]}`를 반환할 수 있다.
이 예시에는 저장 시각·소유자·고유 ID 등이 빠져 있다. 실제 저장은 3·4계율과 v4 스키마 검증을 거친다.
후보에 붙인 이름을 그대로 파일명으로 쓰지 않으며, 보호된 파일명은 13계율에서 별도로 처리한다.

## 7. 상황별 적용 예시

| 발화·상황 | 기대 판단 | 하면 안 되는 처리 |
| --- | --- | --- |
| “맥주 한 잔 했어.” | 개인적 의미가 더 없다면 후보 없음 | 일반적인 맥주 설명 저장 |
| “한강에서 혼자 걷는 게 내 스트레스 해소법이야.” | 한강·걷기 습관의 개인적 맥락 추출 | 감정 단어마다 새 쩜 생성 |
| “강아지 두부와 매일 저녁 산책해. 비 오면 두부가 싫어해.” | 두부와 산책 습관, 비 오는 날의 반응을 구분해 검토 | ‘싫어함’이라는 일반 감정 쩜 생성 |
| 같은 발화를 입력 중 다섯 번 수신 | 같은 입력의 잠정 후보를 재검토 | 언급 횟수 다섯 번 증가 |
| “그 회사에서 해고된 뒤 많이 힘들었어.” | 사건과 당시 맥락 보존 | 감정 때문에 사건 기억 자체 폐기 |
| “핑크는 그때 말한 사람과 다른 친구야.” | 상이하다는 근거를 2·12계율로 전달 | 이름 일치만으로 덮어쓰기 |

## 8. 기억을 만드는 태도

**한 번 만들 쩜은 숙고해서 만들고, 만든 쩜은 함부로 버리지 않는다.**
오래 회상되지 않았다는 이유만으로 쩜 자체를 삭제하지 않는다.
쩜선의 활성도·가중치는 감쇠할 수 있고 미회상 쩜의 기회는 [10계율](10계율_중요도와_우선순위_알고리즘.md)에서 다루지만, 그것이 임의 삭제의 근거가 되지 않는다.
사용자의 명시적 삭제 요청은 추출 판단과 분리해 13계율의 범위 확인을 거친다.

서비스 전용 지식은 추출의 기본 규칙에 넣지 않는다.
판단 대상은 특정 서비스에 얼마나 쓸모 있는지가 아니라 **그 인간에게 어떤 기억인가**이다.

## 9. 검수 기준과 남은 결정

- 후보마다 발화나 허용된 맥락의 근거가 있는가?
- 인용·가정·희망과 실제 경험, 입력 중 문장과 최종 발화를 구분했는가?
- 일반 단어와 감정만으로 쩜을 만들지 않았는가?
- 독립 대상과 그 대상의 사실·선호를 불필요하게 잘게 나누지 않았는가?
- 중복·충돌 판단을 후속 계율에 넘기고 빈 결과도 허용했는가?
- 내부 기억 보존과 파일명 보호를 구분하고 `meta`를 해석하지 않았는가?

미확정: 후보의 최대 개수, 개인적 의미의 정량 기준, 잠정 후보 보존 방식, 세부 감정 관계 데이터 구조.
수치나 저장 구조가 필요하면 현재 확정 문서를 확인하고, 없으면 제안 사항으로 남긴다.
