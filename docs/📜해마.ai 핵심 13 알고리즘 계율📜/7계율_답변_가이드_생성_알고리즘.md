# 7계율 — 답변 가이드 생성 알고리즘

> **기획 명세이며 구현 완료를 뜻하지 않는다.** 해마는 호스트에게 판단 방향과 기억 재료를 건넨다.
> 아래 가이드 기록은 설명용이며 구현된 API 타입, 확정 enum 또는 새 저장 필드가 아니다.

## 역할과 읽는 상황

확정된 유저 발화, 현재 맥락, [6계율 회상](./6계율_회상_알고리즘.md)의 선별 후보를 함께 본다.
호스트가 기억을 언제·어떻게 활용할지 판단할 수 있도록 방향과 주의점을 정리한다.
해마는 최종 문장·말투·캐릭터 표현을 직접 만들지 않고 유저에게 말을 걸지 않는다.

- 읽는 때: 최종 발화에 대한 회상 후보가 정리된 뒤, 호스트의 답변을 지원할 때.
- 호스트가 이야깃거리·선제 안부 재료를 요청했을 때에도 읽는다. 이 경우 최신 사용자 발화가 없어도 요청 근거와 관계·시각 정보를 확인해 검토할 수 있다.
- 검색어: `mode`, `allowed`, `comfortCues`, `forbidden`, `followUpQuestions`, `부정 기억`, `호스트`.
- M1/M2 웹 콘솔은 호스트에게 전달할 상황을 **시뮬레이션**한다.
- 실제 호스트 연결·가이드 전달 규격은 [최신 기획서](../해마.ai_최신기획서.md)의 M4+ 범위다.

## 필요한 입력

1. 유저가 전송한 최종 발화와 필요한 이전 대화. 입력 중 초안은 확정 발언으로 쓰지 않는다.
   선제 안부 요청이라면 현재 시각, 허용된 맥락과 호스트의 요청을 대신 확인한다.
2. 같은 `ownerId`에서 확인된 회상 후보, JJ-tag, 쩜선 근거와 후보의 부정 맥락 주의.
3. [5계율](./5계율_감정_감지_알고리즘_임시.md)의 관찰 신호가 있다면 불확실성 표시까지 함께.
4. 호스트가 제공한 `hint`. 서비스별 표현·역할은 호스트가 정하며 Haema는 `meta` 내용을 해석하지 않는다.
5. M4+에서 실제 관계 데이터가 전달된 경우에만 그 확인된 정보. 아직 없으면 빈 상태로 판단한다.

여러 기억을 묶어도 출처가 없는 감정·관계·의도는 덧붙이지 않는다.
회상 후보가 없다는 사실 자체가 유용한 입력이다.

## 판단 순서와 분기

### 1. 최종 발화의 요구를 읽는다

유저가 질문했는지, 소식을 전했는지, 불편함을 토로했는지 등 발화의 목적을 파악한다.
대화 속 표현과 유저가 실제로 밝힌 내용만 근거로 삼는다.
`ㅋㅋ`·`ㅎㅎ`·`ㅠㅠ`·말줄임, 존댓말·반말·호칭·주어 생략은 한국어 문맥을 함께 보아도 뜻이 여럿일 수 있다.
`됐어요 ㅎㅎ`만 보고 만족·친밀감이나 대화 종료 의도를 확정하지 않는다.
타이핑 중 멈춤이나 삭제는 [5계율](./5계율_감정_감지_알고리즘_임시.md)의 가능성 신호일 뿐 단정적 감정이 아니다.

### 2. 회상 후보의 쓰임을 나눈다

유저가 직접 언급한 쩜은 알아봐 주는 데 쓰일 수 있다.
쩜선으로 연상된 기억은 현재 대화에 도움이 되는지 다시 확인한다.
관련성만 높고 발화 목적에는 불필요한 세부 내용은 넣지 않는다.
부정 기억은 유저가 먼저 꺼냈거나 맥락이 분명히 요구하는지 확인한다.
없으면 선제적으로 구체적 상처를 꺼내는 가이드를 만들지 않는다.

### 3. 응답 방향을 제안한다

`mode`는 공감·축하·안부·조심 안부·가벼운 대화처럼 **방향을 설명하는 예시**다.
고정 목록이나 자동 판정 점수는 이 문서가 정하지 않는다.

일반적인 부정 기억은 선제 이야깃거리로 내보내지 않는다. [PLAN의 예외](../PLAN.md)는
`type="고민"` + `jjtags`의 `미해결`인 경우에 한해 `careful: true`로 **조심 안부** 재료를 주는 것이다.
이때 구체적인 고민 내용을 먼저 말하지 않도록 `forbidden`에 남기고, 안부를 열어도 되는지 호스트가 판단하게 한다.
해결된 고민이나 일반적인 부정 사건에는 이 예외를 적용하지 않는다.
유저가 속상한 일을 말해도 근거 없이 “분노”·“절망”처럼 감정을 강하게 단정하지 않는다.
함께 화내는 방향이 적절해 보여도 폭력·협박의 실제 실행을 부추기는 문장을 해마가 만들지 않는다.

### 4. 사용할 재료와 피할 행동을 분리한다

`allowed`에는 현재 발화에서 확인된 주제와 필요한 기억의 쓰임을 적는다.
`comfortCues`에는 연결된 긍정 기록 등 **존재가 확인된** 위로 단서만 둔다.
`forbidden`에는 상대를 성급히 옹호하기, 훈계하기, 유저가 꺼내지 않은 부정 기억 선제 언급 같은 주의점을 둔다.
후보가 없으면 `comfortCues`를 비워 둔다. 좋은 기억을 꾸며내지 않는다.
개인정보가 불필요하게 드러날 수 있으면 [13계율](./13계율_개인정보_및_민감정보_처리_알고리즘.md)로 범위를 줄인다.

### 5. 이어묻기 필요성만 표시한다

별칭의 주인, 사건의 시기, 개인 표현의 뜻이 불분명하면 `followUpQuestions`에 확인할 **질문 후보**를 둔다.
이는 호스트의 선택지이지 해마가 유저에게 보내는 발화가 아니다.
근거가 약하면 질문 없이 듣는 방향도 정상이다.
모호한 기억의 병합을 질문 하나 없이 확정하지 않는다. 동일 대상 검토는 [2계율](./2계율_기존_쩜_탐색_알고리즘.md)로 넘긴다.

### 6. 호스트에 전달한다

현재 맥락과 가이드를 함께 전달하되 호스트의 자체 안전 규칙·말투·최종 답변 권한을 침범하지 않는다.
호스트의 존댓말·반말·호칭 선택은 확인된 유저 선호와 서비스 환경에 맡긴다. 한국 사용자라는 이유만으로 선호를 일반화하지 않는다.
한국어 원문을 영문 번역으로 바꾼 문장만 전달해 조사·말투·중의성을 지우지 않는다.
M1/M2에서는 콘솔의 미리보기일 뿐 실제 호스트가 받았다고 기록하지 않는다.
실제 답변을 받지 않은 상태에서 [8계율](./8계율_호스트_답변_평가_알고리즘.md)을 실행한 것처럼 표시하지 않는다.

## 출력: 해마 판단 기록의 예

가이드의 다섯 갈래는 **설명용 구성**이다. 각 갈래의 내용이 없는 경우 빈 상태로 남길 수 있다.

> 맥락: 유저가 친구와의 갈등을 직접 말했다.
> `mode`: 먼저 듣고 공감하는 방향.
> `allowed`: 유저가 말한 갈등과 확인된 친구 쩜을 알아봐 주기.
> `comfortCues`: 현재 근거 있는 긍정 기억이 없으므로 없음.
> `forbidden`: 상대를 변호하거나 과거 상처를 먼저 꺼내지 않기.
> `followUpQuestions`: 호스트가 필요하다고 판단하면 갈등의 맥락을 확인할 후보.

해마는 위 문장을 최종 채팅 답변으로 내보내지 않는다.
쩜의 설명·정렬은 [6계율](./6계율_회상_알고리즘.md)과 [10계율](./10계율_중요도와_우선순위_알고리즘.md)의 근거에 따른다.

## 가상 예시

### 예시 1 — 친구를 기억한 주말 대화

유저: “이번 주말 뭐 하지?”
회상에서 핑크와의 약속 맥락이 확인됐다면 호스트에 친구와의 계획을 떠올릴 재료를 준다.
“핑크랑 만나”라는 지시나 호스트의 실제 대사는 쓰지 않는다.

### 예시 2 — 이름 없는 좋은 기억

유저: “요즘 힘드네.”
호스트가 요청한 JJ-tag cue로 실제 좋은 기억이 회상됐다면 그것을 `comfortCues` 후보로 둔다.
기억의 관련성이 약하거나 유저가 지금 원하지 않을 수 있으면 조용히 듣는 방향도 남긴다.

### 예시 3 — 부정 기억을 유저가 먼저 꺼냄

유저: “안**이 약속을 안 지켰어.”
부정 기억을 알아봐 주되 상대 옹호·훈계를 피하라는 주의점을 준다.
시나리오의 “편들기”는 유저의 맥락을 존중하는 방향이지 기억에 없는 사실을 단정하는 허가가 아니다.

### 예시 4 — 뜻이 불분명한 표현

유저: “샤갈! 오늘 그랬어.”
화가나 사람을 뜻한다고 정하지 않는다. 필요하면 의미를 확인할 질문 후보만 호스트에 건넨다.
`그랬어`의 생략된 주어와 지시 대상도 앞선 대화에서 확인되지 않으면 만들어 넣지 않는다.
질문할지, 어떤 말투로 물을지는 호스트가 정한다.

### 예시 5 — 회상 후보 없음

새 주제이고 관련 쩜이 없다.
기억을 아는 척하지 않는 방향과 필요한 경우에만 이어묻기 후보를 전달한다.
없는 긍정 기억으로 `comfortCues`를 채우지 않는다.

## 보류·실패 처리

- 대화 응답용 가이드는 최종 발화 없이 확정하지 않는다. 호스트가 별도로 요청한 선제 안부는 그 요청·시각·허용 맥락을 기준으로 검토한다.
- 회상 후보가 비면 빈 기억 기반의 가이드를 만든다. 허구의 쩜을 보태지 않는다.
- 부정 맥락의 노출 목적이 불명확하면 선제 언급을 보류한다.
- 관계 데이터가 없거나 M4+ 연동이 준비되지 않았으면 유저 선호를 꾸며내지 않는다.
- 가이드 작성에 실패해도 호스트가 현재 발화를 받는 흐름을 해마가 막지 않는다.
- 실제 사용자 반응이 없으면 가이드의 성공 여부는 [8계율](./8계율_호스트_답변_평가_알고리즘.md)에서 보류한다.

## 검수 기준

- 최종 발화와 입력 중 스냅샷을 혼동하지 않는가?
- 다섯 갈래가 호스트용 판단 재료이고 최종 답변 문장이 아닌가?
- 부정 기억의 선제 노출과 훈계·상대 옹호를 필요한 경우 금지하는가?
- 확인되지 않은 좋은 기억·관계 정보·감정을 만들지 않는가?
- 질문은 호스트에 넘기는 후보일 뿐 해마가 직접 묻지 않는가?
- `meta` 내용으로 서비스별 응답 분기를 만들지 않는가?
