# 해마.ai — 기억·파워·회상 13개 알고리즘

> **이 문서는 13개 계율의 진입점이다.** 지금 처리할 상황을 찾고 필요한 계율만 읽는다.
> 각 계율은 한국어 기획 명세다. 문서 작성, 코드 구현, 실제 동작 검증은 서로 다른 완료 항목이다.
> 2026-10-08~09 기획팀 회의 내용을 반영했다. 기존 링크를 위해 알고리즘 파일명은 유지하며, 문서 제목은 현재 역할에 맞췄다. 5계율의 옛 파일명에 남은 `임시`는 감정 배점이 미정이라는 뜻이 아니다.

## 1. 읽기 전에 확인할 원칙

**우선 타깃은 한국이다.** 한국어 원문과 한국 사용 환경의 표현을 먼저 검증한다.
조사·띄어쓰기·호칭·별명·신조어·생략은 문맥과 함께 해석하고, `ㅋㅋ`·`ㅎㅎ`·존댓말만으로 감정이나 관계를 단정하지 않는다.
한국 사용자라는 이유로 모두 같은 말투·관계 관습·시간대를 가진다고 가정하지 않는다. 날짜 해석은 전달받은 시각·시간대를 근거로 한다.

해마는 기억을 관리하고 호스트 AI에게 재료와 가이드를 전달한다. 사용자와 실제로 대화하는 주체는 호스트 AI다.
로컬 테스트에서는 이 전달 상황을 확인하며, 해마의 결과를 호스트의 실제 답변이나 사용자의 실제 반응으로 취급하지 않는다.

세션에 정상적으로 제공된 상위 정체성·행동 원칙을 유지한 상태에서 이 목록을 사용한다.
이 문서는 비공개 상위 문서의 내용을 대신 만들거나, 불러오지 못한 문서를 읽었다고 가정하지 않는다.

필요한 문서를 읽은 뒤에도 근거가 부족하면 보류한다. **후보 없음, 근거 부족, 처리 실패는 서로 다른 결과**다.
문서를 여러 개 읽었다는 사실만으로 불확실한 판단을 확정하지 않는다.

## 3. 대표적인 처리 순서

### 대화를 기억으로 남길 때

```text
11 세션과 입력 상태 확인
  → 1 개인적 의미 추출
  → 2 기존 대상 탐색
       ├─ 동일 대상의 새 정보 → 3 갱신
       ├─ 별개 대상 → 4 생성
       └─ 동일성 불명·모순 → 12 판단 후 2·3·4로 복귀
  → 최종 발화 기준 재검토와 저장

민감정보나 노출 위험이 있는 단계에서는 13을 먼저 적용한다.
감정·과거 사건 점수는 5, 네 항의 파워 계산은 10을 함께 읽는다.
```

### 기억을 호스트에게 전달할 때

```text
현재 발화·허용된 맥락
  → 6 회상 후보 찾기
  ↔ 10 관련성과 우선순위 판단
  ↔ 필요할 때 9 미래 대화 가능성 탐색
  → 13 전달할 범위 확인
  → 7 답변 가이드
  → 호스트 AI
  → 실제 답변과 후속 반응이 도착하면 8 평가
```

이는 문서 선택과 책임 분담을 설명한 순서다. 현재 서버의 호출 함수나 자동 문서 검색 기능을 뜻하지 않는다.
실시간 스냅샷은 잠정 분석에만 쓰고 확정 발화에서 저장·집계한다. 단편 대화의 새 근거만 누적하며, 재전송·세션 재개로 이미 처리한 발화를 다시 세지 않는다. 계약은 11계율과 [발화 API](../CONVERSATION_API.md)를 따른다.

## 4. 모든 계율이 공유하는 기준

| 구분 | 공통 기준 |
| --- | --- |
| 기억 단위 | 개인적 의미가 있는 쩜을 신중히 만든다. 일반 지식·감정 단어 자체를 쩜으로 늘리지 않는다. |
| 동일성 | 이름·별칭·뜻이 비슷한 것은 탐색 근거다. 동명이인과 불확실한 대상을 임의로 합치지 않는다. |
| 근거 | 사용자 사실, 해마의 해석, 미래 가정, 호스트의 발화를 구분한다. 추측을 사용자 사실로 저장하지 않는다. |
| 기억 보존 | 오래 쓰지 않았다고 쩜을 임의 삭제하지 않는다. 옛 점수 방식의 폐기는 개인 기억 삭제 권한이 아니다. |
| 파워와 회상 | 파워는 삶에 미치는 영향의 크기다. 회상 R은 매 발화 새로 판단하며 높은 파워가 매번 회상을 강제하지 않는다. |
| AI의 판단 | 노출 기간·감정·타입 계수·연결 굵기·같은 과거 사건인지 여부를 맥락으로 판단한다. 추정은 대화로 수정한다. |
| 데이터 구조 | `schemaVersion=4`, `jjtags`, `active / resting / merged` 등 [스키마](../SCHEMA.md)를 따른다. |
| 파일명 | 파일명 마스킹과 내부 `jjumName`·기억 내용 보존을 구분한다. ID를 이름이나 파일명으로 대신하지 않는다. |
| 개인정보 | 기억에 필요한 범위만 다루며, 고위험 정보 처리와 명시적 사용자 제한을 반영한다. |
| 사용자 경계 | `ownerId`가 다른 기억을 섞지 않는다. 계정 인증 방식은 호스트와 실행 환경의 책임이다. |
| 도메인 무지 | 해마는 `meta` 내용을 해석하지 않는다. 특정 서비스의 규칙을 범용 계율에 넣지 않는다. |
| 호스트 경계 | 질문 후보와 가이드는 전달할 수 있지만, 최종 답변·말투·발화 여부는 호스트의 몫이다. |
| 조심 안부 | 부정 기억의 선제 노출은 피한다. 미해결 고민만 6·7계율에 따라 상세 내용 없는 조심 안부 재료로 검토한다. |
| 선택적 Laya | 2차 판단 보조다. 원문 생성이나 최종 결정권을 맡기지 않는다. 실패 시 사용 가능한 해마 판단 경로로 돌아간다. |
| 빈 결과와 실패 | 후보가 없는 것은 정상일 수 있다. 입력·저장소·모델 오류는 실패로 따로 알린다. |

## 5. 다음 계율로 넘길 때

각 계율은 **무엇을 판단했고, 어떤 근거가 있으며, 무엇이 아직 미정인지**를 다음 처리에 전달한다.
긴 사고 과정 대신 원문에서 확인되는 근거와 처리에 필요한 결론을 간결하게 남긴다.

| 전달할 내용 | 확인할 사항 |
| --- | --- |
| 사용자·세션·입력 시각과 확정 여부 | 같은 발화의 재처리를 다른 사람·새 발화로 오인하지 않는가? |
| 대상 후보와 확인된 쩜 ID | 후보 이름을 실제 ID로 꾸며내지 않았는가? |
| 필요한 근거와 판단 결과 | 사실·해석·가정이 구별되어 있는가? |
| 보류·제외·실패 이유 | 모르는 내용을 빈 성공으로 숨기지 않았는가? |
| 다음 문서와 필요한 추가 정보 | 같은 문서를 근거 없이 무한 반복해서 읽지 않는가? |
| 저장·전달 제한 | 민감한 원문을 중간 기록에 다시 복제하지 않았는가? |

이 표와 각 문서의 출력 예시는 **의미상 필요한 정보의 설명**이다.
새 필수 필드나 통신 규격을 확정한 것이 아니며, 실제 저장은 v4 스키마를 따른다.

## 6. 기획서 사이에 차이가 있을 때

1. 이번 기획팀 회의에서 합의한 기준을 이 묶음의 3·4·5·6·10·11·12계율에 반영했다. **점수·쩜선 동작은 이 최신 결정을 우선한다.**
2. [SCHEMA.md](../SCHEMA.md)는 현재 파일 형식·필드·상태·파일명 규칙, [발화 API](../CONVERSATION_API.md)는 발화 식별·저장 계약의 기준이다. 이 문서 수정만으로 저장 구조나 구현이 바뀌지는 않는다.
3. SCHEMA와 [기존 기획서](../해마.ai_최신기획서.md)의 ‘다른 세 항 환산식·복수 타입 방식 미정’, ‘공동 언급이면 신규 4.0·자동 양쪽 강화’ 문구는 이번 점수 기획에 적용하지 않는다. 기존 소수점 원값과 7단계 표시를 현재 데이터에서 어떻게 이행할지는 백엔드가 별도로 설계한다.
4. [사용 시나리오](../USAGE_SCENARIOS.md)와 [PLAN.md](../PLAN.md)는 나머지 기대 동작·개발 배경으로 참고한다. 사실·AI 추정·가상 미래는 계속 구별한다.

## 7. 확정 사항과 개발에 필요한 작업

- **파워 네 항:** [10계율의 파워 기준](10계율_중요도와_우선순위_알고리즘.md)에 계산식과 검산 예시를 모았다. 언급은 복수 타입 α 평균·β 최댓값, 기간은 추정 일수, 감정은 누적 합, 쩜선은 각 선의 소수점 굵기 원값 합이다.
- **과거 사건:** AI가 사건 쩜을 만들거나 같은 기존 사건을 찾는다. 해당 쩜에 대한 사건 점수 303·33점은 같은 사건에 한 번만, 다시 말하는 날의 감정 1~3점은 추가한다. 자세한 사례는 [5계율의 감정·과거 사건 기준](5계율_감정_감지_알고리즘_임시.md)을 따른다.
- **쩜선·회상:** AI가 연상의 깊이를 판단한다. 연결 굵기와 현재 발화의 회상 관련성 R은 별개이며, 같은 연결도 출발 방향과 문맥에 따라 회상 효과가 다르다. 4·6계율을 따른다.
- **누적:** 사용자 선행 언급만 N에 반영하며 최종 발화당 동일 쩜 최대 1회다. 초기 N=1과 생성 발화를 중복 가산하지 않는다. 재처리·재전송은 추가 집계하지 않는다.
- **백엔드 설계·검증:** 각 항과 추정 근거의 저장 형식, AI 판단 결과의 계약·검증·실패 처리, 사건 식별과 일회 가산 기록, 정정·재시도 처리 및 기존 데이터 호환이 필요하다. 이를 점수 정의 미정이나 구현 완료로 표현하지 않는다.
- **별도 미정:** 쩜선 갱신의 일반 규칙, 연상 가산을 R에 반영하는 수식·MCTS 세부 정책, 병합·복원, 입력 관찰 기록과 상세 관계 데이터 구조. 파워 항의 합산식과 구별한다.
- **균형 검증:** 기간 점수가 다른 항보다 크게 나올 수 있다. 현재 수식대로 비교하고, 임의 정규화·배율 변경은 하지 않는다.

스냅샷 0.5초·대기 3초·비활성 5초는 11계율의 기존 기획을 유지한다. R 분류·콘솔 표시 범위는 6계율을 따른다. 후보가 없으면 화면을 채우려고 기억을 만들지 않는다.

## 8. 문서로 검수할 때

상황 하나를 골라 위 표에서 시작하고, 다른 문서를 불필요하게 모두 읽지 않고도 처리 방향을 찾을 수 있는지 확인한다.
각 문서의 가상 예시는 기대 결과를 검토하는 용도이며 자동 테스트 통과 기록이 아니다.
가상 예시는 검수용이다. 별도로 표시한 대화 예시는 기획팀에서 논의한 내용을 이름 마스킹 후 정리했으며, 제3자에 대한 사실 검증이나 실제 기억 데이터 추출을 뜻하지 않는다.
실제 구현 상태와 로컬 실행 방법은 [LOCAL_TEST.md](../LOCAL_TEST.md)를 별도로 확인한다.

**이 문서 묶음의 완료 범위는 상황별 명세 작성이다.**
자동 문서 탐색·주입, 알고리즘 실행 코드 변경, MCTS 구현, 외부 호스트 연결은 이 문서 작업만으로 완료되지 않는다.
