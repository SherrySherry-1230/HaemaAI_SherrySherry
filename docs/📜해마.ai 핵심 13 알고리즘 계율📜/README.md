# 해마.ai — 상황별 알고리즘 읽기 목록

> **이 문서는 13개 계율의 진입점이다.** 지금 처리할 상황을 찾고 필요한 계율만 읽는다.
> 각 계율은 한국어 기획 명세다. 문서 작성, 코드 구현, 실제 동작 검증은 서로 다른 완료 항목이다.
> 기존 파일명을 유지했으며, 5계율 파일명의 `임시` 표기도 현재 미확정 범위를 나타내므로 유지한다.

## 1. 읽기 전에 확인할 원칙

**우선 타깃은 한국이다.** 한국어 원문과 한국 사용 환경의 표현을 먼저 검증한다.
조사·띄어쓰기·호칭·별명·신조어·생략은 문맥과 함께 해석하고, `ㅋㅋ`·`ㅎㅎ`·존댓말만으로 감정이나 관계를 단정하지 않는다.
한국 사용자라는 이유로 모두 같은 말투·관계 관습·시간대를 가진다고 가정하지 않는다. 날짜 해석은 전달받은 시각·시간대를 근거로 한다.

해마는 기억을 관리하고 호스트 AI에게 재료와 가이드를 전달한다. 사용자와 실제로 대화하는 주체는 호스트 AI다.
로컬 테스트에서는 이 전달 상황을 확인하며, 해마의 결과를 호스트의 실제 답변이나 사용자의 실제 반응으로 취급하지 않는다.

세션에 정상적으로 제공된 상위 정체성·행동 원칙을 유지한 상태에서 이 목록을 사용한다.
이 문서는 비공개 상위 문서의 내용을 대신 만들거나, 불러오지 못한 문서를 읽었다고 가정하지 않는다.

필요한 문서를 읽은 뒤에도 근거가 부족하면 보류한다. **후보 없음, 근거 부족, 처리 실패는 서로 다른 결과**다.
문서를 여러 개 읽었다는 사실만으로 불확실한 판단을 확정하지 않는다.

숫자는 이 폴더의 계율 번호다. 같은 행의 모든 문서를 매번 읽을 필요는 없다.
예를 들어 저장할 후보가 없다면 신규 생성 문서까지 읽지 않아도 된다.
개인정보 처리는 마지막에 한 번만 하는 절차가 아니라, 저장·갱신·회상·외부 전달에서 필요할 때마다 적용한다.

## 3. 대표적인 처리 순서

### 대화를 기억으로 남길 때

```text
11 세션과 입력 상태 확인
  → 1 개인적 의미 추출
  → 2 기존 대상 탐색
       ├─ 동일 대상의 새 정보 → 3 갱신
       ├─ 별개 대상 → 4 생성
       └─ 동일성 불명·모순 → 12 판단 후 2·3·4로 복귀
  → 최종 발화 기준 재검토와 저장

민감정보나 노출 위험이 있는 단계에서는 13을 먼저 적용한다.
입력 변화 신호가 필요하면 5를 함께 읽는다.
```

### 기억을 호스트에게 전달할 때

```text
현재 발화·허용된 맥락
  → 6 회상 후보 찾기
  ↔ 10 관련성과 우선순위 판단
  ↔ 필요할 때 9 미래 대화 가능성 탐색
  → 13 전달할 범위 확인
  → 7 답변 가이드
  → 호스트 AI
  → 실제 답변과 후속 반응이 도착하면 8 평가
```

이는 문서 선택과 책임 분담을 설명한 순서다. 현재 서버의 호출 함수나 자동 문서 검색 기능을 뜻하지 않는다.
실시간 스냅샷과 최종 발화를 구분하며, 잠정 결과의 영구저장 시점은 11계율의 미확정 항목을 확인한다.

## 4. 모든 계율이 공유하는 기준

| 구분 | 공통 기준 |
| --- | --- |
| 기억 단위 | 개인적 의미가 있는 쩜을 신중히 만든다. 일반 지식·감정 단어 자체를 쩜으로 늘리지 않는다. |
| 동일성 | 이름·별칭·뜻이 비슷한 것은 탐색 근거다. 동명이인과 불확실한 대상을 임의로 합치지 않는다. |
| 근거 | 사용자 사실, 해마의 해석, 미래 가정, 호스트의 발화를 구분한다. 추측을 사용자 사실로 저장하지 않는다. |
| 기억 보존 | 오래 쓰지 않았다고 쩜을 임의 삭제하지 않는다. 쩜선 감쇠와 쩜 보존은 구분한다. |
| 데이터 구조 | `schemaVersion=4`, `jjtags`, `active / resting / merged` 등 [스키마](../SCHEMA.md)를 따른다. |
| 파일명 | 파일명 마스킹과 내부 `jjumName`·기억 내용 보존을 구분한다. ID를 이름이나 파일명으로 대신하지 않는다. |
| 개인정보 | 기억에 필요한 범위만 다루며, 고위험 정보 처리와 명시적 사용자 제한을 반영한다. |
| 사용자 경계 | `ownerId`가 다른 기억을 섞지 않는다. 계정 인증 방식은 호스트와 실행 환경의 책임이다. |
| 도메인 무지 | 해마는 `meta` 내용을 해석하지 않는다. 특정 서비스의 규칙을 범용 계율에 넣지 않는다. |
| 호스트 경계 | 질문 후보와 가이드는 전달할 수 있지만, 최종 답변·말투·발화 여부는 호스트의 몫이다. |
| 조심 안부 | 부정 기억의 선제 노출은 피한다. 미해결 고민만 6·7계율에 따라 상세 내용 없는 조심 안부 재료로 검토한다. |
| 선택적 Laya | 2차 판단 보조다. 원문 생성이나 최종 결정권을 맡기지 않는다. 실패 시 사용 가능한 해마 판단 경로로 돌아간다. |
| 빈 결과와 실패 | 후보가 없는 것은 정상일 수 있다. 입력·저장소·모델 오류는 실패로 따로 알린다. |

## 5. 다음 계율로 넘길 때

각 계율은 **무엇을 판단했고, 어떤 근거가 있으며, 무엇이 아직 미정인지**를 다음 처리에 전달한다.
긴 사고 과정 대신 원문에서 확인되는 근거와 처리에 필요한 결론을 간결하게 남긴다.

| 전달할 내용 | 확인할 사항 |
| --- | --- |
| 사용자·세션·입력 시각과 확정 여부 | 같은 발화의 재처리를 다른 사람·새 발화로 오인하지 않는가? |
| 대상 후보와 확인된 쩜 ID | 후보 이름을 실제 ID로 꾸며내지 않았는가? |
| 필요한 근거와 판단 결과 | 사실·해석·가정이 구별되어 있는가? |
| 보류·제외·실패 이유 | 모르는 내용을 빈 성공으로 숨기지 않았는가? |
| 다음 문서와 필요한 추가 정보 | 같은 문서를 근거 없이 무한 반복해서 읽지 않는가? |
| 저장·전달 제한 | 민감한 원문을 중간 기록에 다시 복제하지 않았는가? |

이 표와 각 문서의 출력 예시는 **의미상 필요한 정보의 설명**이다.
새 필수 필드나 통신 규격을 확정한 것이 아니며, 실제 저장은 v4 스키마를 따른다.

## 6. 기획서 사이에 차이가 있을 때

1. 쩜의 필드·상태·용어·파일명은 단일 기준으로 명시된 [SCHEMA.md](../SCHEMA.md) v4를 따른다.
2. 전체 흐름과 M1~M5 범위는 [최신 기획서](../해마.ai_최신기획서.md)를 따른다.
3. 개인적 의미 추출·감정 독립 쩜 금지·기억 보존은 대표님이 보강한 1계율의 의도를 반영한다.
4. [사용 시나리오](../USAGE_SCENARIOS.md)는 기대 사례로, [PLAN.md](../PLAN.md)는 세부 개발 배경으로 참고한다.
5. 어느 기준으로도 해결되지 않는 결정은 각 문서의 미확정 항목으로 남기고 설계 확인 대상으로 보낸다.

PLAN의 과거 경로·상태명·고정 탐색 거리와, 최신 스키마의 선택 저장소·상태·MCTS 방향을 섞지 않는다.
최신 기획서에 `MTCS`라고 적힌 미래 탐색은 스키마와 기존 9계율의 `MCTS` 표기에 맞췄다.
시나리오의 관계 추론은 확인된 사실과 분리한다. “반복해 만남”만으로 사용자가 말하지 않은 관계 호칭을 확정하지 않는다.

## 7. 아직 수치나 구조를 확정하지 않은 부분

- 추출·동일성 판단의 임계값, 후보 수 제한과 불확실성 표현 방식.
- 입력 중 후보의 저장·철회 방식, 세션 복구 기록과 중복 처리 방지 방식.
- MCTS의 평가 함수, 탐색 예산, 회상 점수 결합식과 쩜선 감쇠율.
- 미회상 쩜 보너스 수치, 상세 관계 데이터와 감정 데이터의 구조.
- 병합·복원 시 원래 기록을 완전하게 복구하는 보관 방식.
- 개인정보 탐지의 세부 기준, 파일명 충돌 방지, 사용자 삭제 요청의 전체 반영 범위.

다만 기획서에 정해진 **스냅샷 0.5초, 대기 3초, 비활성 5초**는 11계율에서 그대로 다룬다.
강력 추천 1~3개·관련 쩜 0~13개는 콘솔의 표시 범위다. 근거가 부족할 때 그 수를 채우려고 기억을 만들지 않는다.
구체적 판단 기준과 남은 결정은 해당 계율에 이어서 적었다.

## 8. 문서로 검수할 때

상황 하나를 골라 위 표에서 시작하고, 다른 문서를 불필요하게 모두 읽지 않고도 처리 방향을 찾을 수 있는지 확인한다.
각 문서의 가상 예시는 기대 결과를 검토하는 용도이며 자동 테스트 통과 기록이 아니다.
등장하는 사람·이름·장소·대화는 설명을 위한 가상 예시이며 실제 개인 기록을 가져온 것이 아니다.
실제 구현 상태와 로컬 실행 방법은 [LOCAL_TEST.md](../LOCAL_TEST.md)를 별도로 확인한다.

**이 문서 묶음의 완료 범위는 상황별 명세 작성이다.**
자동 문서 탐색·주입, 알고리즘 실행 코드 변경, MCTS 구현, 외부 호스트 연결은 이 문서 작업만으로 완료되지 않는다.
