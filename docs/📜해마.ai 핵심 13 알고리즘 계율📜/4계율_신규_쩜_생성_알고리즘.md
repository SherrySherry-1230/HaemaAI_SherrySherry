# 4계율 · 신규 쩜 생성 알고리즘

> 해마.ai 핵심 13 알고리즘 계율 · 기획 명세, 구현 완료를 뜻하지 않음.
> 목적: 개인에게 의미 있는 새 기억만 v4 쩜(JJum)으로 만든다.
> 아래 판단 기록은 설명용이며 구현된 API 또는 새 필수 저장 필드를 뜻하지 않는다.

## 역할과 경계

신규 생성은 [1계율](./1계율_쩜_추출_알고리즘.md)이 개인적 의미를 확인하고 [2계율](./2계율_기존_쩜_탐색_알고리즘.md)이 기존 쩜과의 관계를 살핀 뒤 수행한다.
단어가 등장했다는 이유만으로 파일을 늘리지 않는다.
같은 대상의 확인된 기존 쩜이 있다면 [3계율](./3계율_기존_쩜_업데이트_알고리즘.md)의 갱신으로 돌린다.
이름이 같거나 의미가 비슷한 후보만으로 기존 쩜과 자동 병합하지 않는다.
사용자가 아직 보내지 않은 스냅샷의 후보와 최종 확정 발화의 생성 판단을 구별한다.
새 쩜을 만든 뒤 사람에게 답변할지는 호스트가 결정한다.
Haema는 서비스별 meta 내용을 해석하지 않는다.

### 이 문서를 읽는 상황 · 검색어

- 사용자의 새 경험·선호·관계가 처음 등장했을 때: “신규 쩜”, “개인적 의미”.
- 기존 쩜 탐색에서 일치 대상이 없었을 때: “새 기억”, “중복 방지”.
- 이름을 정하거나 별칭을 붙여야 할 때: “jjumName”, “aliases”.
- 파일명 노출이 걱정될 때: “마스킹”, “.jj”, “내부 이름”.
- 새 사실·사건·쩜태그를 담아야 할 때: “facts”, “events”, “jjtags”.
- 표현이 모호하거나 민감한 정보가 섞였을 때: “보류”, “확인”, “개인정보”.

## 필요한 입력

1. 현재 ownerId, sourceService, 사용자 발화와 그 시점.
2. [1계율](./1계율_쩜_추출_알고리즘.md)이 제시한 개인적 의미 후보와 원문 근거.
3. [2계율](./2계율_기존_쩜_탐색_알고리즘.md)이 확인한 기존 쩜 탐색 결과 및 보류 사유.
4. 대표 이름과 별칭의 근거, 종류, 쩜태그(JJ-tag), 사실·사건·맥락 후보.
5. 함께 등장한 저장 쩜이 있다면 확인된 jjumId.
6. 민감한 이름이나 고위험 정보가 있는지에 대한 [13계율](./13계율_개인정보_및_민감정보_처리_알고리즘.md)의 보호 판단.

모든 저장 필드의 의미와 형식은 [v4 스키마](../SCHEMA.md)를 따른다.
ownerId는 기억의 주인을 구분하는 문자열이며, 인증의 발급·검증은 이 문서가 다루지 않는다.
sourceService는 출처 표식이지 서비스 도메인 규칙을 하드코딩하라는 뜻이 아니다.
meta가 주어지면 불투명한 확장 값으로 보존하며 내용을 보고 생성 여부를 바꾸지 않는다.

## 생성 판단 단계

### 1. 기억할 만한 개인 정보인지 확인한다

사용자에게 실제로 의미 있는 사실·경험·관계·취향·사건인지 본다.
일반 지식이나 사전적 뜻, 일회성 잡음이면 새 쩜을 만들지 않는다.
하나의 발화에 독립적인 기억이 여럿 있으면 각각 검토한다.
같은 사건의 다른 묘사를 무조건 별도 쩜으로 쪼개지 않는다.
독립 쩜과 기존 쩜의 세부 내용 중 어느 쪽이 맞는지 먼저 살핀다.
감정 표현만으로 감정 자체의 독립 쩜을 생성하지 않는다. 대표님이 보강한 [1계율](./1계율_쩜_추출_알고리즘.md)의 현재 기준이다.
사건과 연결된 감정은 해당 기억의 맥락으로 다루고, 의미 불명 신조어는 1계율에 따라 확인한다. 민감정보는 [13계율](./13계율_개인정보_및_민감정보_처리_알고리즘.md)을 따른다.

### 2. 중복·정체성 판단을 다시 확인한다

[2계율](./2계율_기존_쩜_탐색_알고리즘.md)이 기존 쩜 없음으로 판정한 이유를 확인한다.
저장소 읽기에 실패했다면 “없음”으로 간주하지 않고 생성을 보류한다.
정확한 같은 이름이 있어도 동명이인일 수 있으므로 사용자 맥락을 본다.
다른 이름이지만 같은 대상이라는 명시적 근거가 있으면 새 파일 대신 갱신·통합 검토로 넘긴다.
의미 유사도나 쩜선 연결만으로 동일성을 확정하지 않는다.
서로 다른 기존 쩜을 합쳐야 한다면 [12계율](./12계율_쩜_충돌_및_정보_갱신_알고리즘.md)이 다룬다.

### 3. 잠정 입력과 확정 발화를 나눈다

입력 중 스냅샷에서는 생성될 수 있는 쩜 후보와 근거만 표시한다.
사용자가 문장을 고치거나 지우면 앞선 잠정 후보도 다시 계산한다.
전송 버튼 또는 Enter로 최종 발화가 확정되면 그 문장을 기준으로 생성 여부를 다시 결정한다.
최종 확정 전에 파일이 반드시 생겨야 한다고 이 문서가 단정하지 않는다.
잠정 후보의 영구 저장 시점은 최신 기획서에 세부 규칙이 없어 미확정으로 남긴다.

### 4. 신원과 내용의 경계를 세운다

jjumId는 새 쩜에 자동 생성되는 고유 ID다.
사용자가 입력한 이름이나 파일명을 jjumId로 사용하지 않는다.
jjumName에는 대표 이름을, aliases에는 같은 대상임이 확인된 다른 이름을 둔다.
“핑크랑”은 조사 포함 발화일 수 있으므로 그 전체를 신규 jjumName으로 바로 쓰지 않는다.
그러나 모든 끝 글자를 기계적으로 잘라 이름을 만들지도 않는다.
동명이인의 이름이 같아도 서로 다른 jjumId를 사용한다.
“언니”·“선배”·“우리 엄마”만으로 여러 사람을 하나의 쩜으로 합치지 않는다.
띄어쓰기·분명한 오탈자와 “그 사람” 같은 지시어는 원문 문맥으로 확인한다.
type은 개방형이며 특정 서비스만의 종류를 코어 규칙으로 고정하지 않는다.
jjtags에는 여러 쩜태그를 둘 수 있고 정서가도 쩜태그의 한 종류다.
summary는 근거에 맞는 한 줄 요약이어야 하며 빈칸을 상상으로 채우지 않는다.
facts에는 사실의 텍스트·추가 시점·출처를, events에는 날짜·요약·확인된 관련 쩜 ID를 담는다.
context는 실제 대화·환경의 맥락을 필요한 범위에서 담는다.
“어제” 같은 상대 날짜는 입력 시각과 전달된 시간대가 충분하지 않으면 확정 날짜로 기록하지 않는다.
한국 우선 타깃이어도 사용자의 말투·감정·시간대를 한 가지 값으로 고정하지 않는다.
관련 이름만 알아서는 events의 refJJumIds나 seons의 targetId에 이름을 넣지 않는다.

### 5. 통계·관리 필드를 초기화한다

v4 스키마의 mentionCount, firstSeen, lastMentioned, recallCount를 구별한다.
첫 언급과 첫 회상은 다른 사건이다. 저장과 동시에 회상이 일어났다고 가정하지 않는다.
pinned, status, mergedFrom, editHistory, responseFeedback의 의미를 유지한다.
새 쩜을 다른 쩜에 이미 병합된 상태라고 임의로 표시하지 않는다.
통계의 구체적 초기값은 스키마와 실제 생성 헬퍼에 맞추며 새 점수 공식을 만들지 않는다.
중요도·신뢰도라는 별도 필수 필드는 v4에 없으므로 만들어 넣지 않는다.
schemaVersion은 현재 기준인 4를 사용한다.

### 6. 파일명과 개인정보를 보호한다

파일 어댑터는 쩜 하나를 .jj 파일 하나로 둔다.
내부 jjumName과 사람이 보는 파일명은 별개다.
사용자의 한글 이름·표현은 내부에 한글로 보존하며 로마자 변환을 강제하지 않는다.
실명·특정 상품·브랜드·욕설이 파일명으로 드러나면 [v4 스키마](../SCHEMA.md)의 보호 규칙을 적용한다.
예를 들어 내부 jjumName이 “홍길동”이어도 파일명은 “홍O동.jj”처럼 가릴 수 있다.
마스킹은 파일명에 적용하며 summary·facts·events를 무조건 지우거나 변형하지 않는다.
고위험 식별 정보의 절삭·마스킹 판단은 [13계율](./13계율_개인정보_및_민감정보_처리_알고리즘.md)을 따른다.
영문 고유명칭의 구체적 마스킹 방식은 스키마 설명이 미완성이라 임의 확정하지 않는다.
보호된 파일명을 다시 내부 이름으로 역추정하지 않는다.

### 7. 쩜선과 후속 판단을 넘긴다

새 쩜과 기존 쩜의 관계가 근거로 확인되면 쩜선 생성을 검토한다.
쩜선의 targetId는 저장된 상대의 실제 jjumId여야 한다.
같은 상대·같은 label의 쩜선은 중복을 만들지 않고, 다른 label은 별도 연결이 가능하다.
weight 수치나 강화 공식은 이 문서에서 새로 정하지 않는다.
지금 꺼낼 기억의 선택은 [6계율](./6계율_회상_알고리즘.md), 호스트 답변 방향은 [7계율](./7계율_답변_가이드_생성_알고리즘.md)로 넘긴다.
생성 직후의 새 쩜이 반드시 대화에 등장해야 한다는 뜻은 아니다.

## 분기 · 출력 · 넘길 문서

| 상황 | 판단 기록 | 다음 단계 |
| --- | --- | --- |
| 개인적 의미가 있고 기존 대상 없음 | 신규 생성 대상 | v4 쩜 생성·저장 검토 |
| 확인된 기존 쩜이 있음 | 중복 생성하지 않음 | [3계율](./3계율_기존_쩜_업데이트_알고리즘.md) |
| 이름·의미가 비슷하지만 정체성 불확실 | 생성·갱신 모두 보류 | [2계율](./2계율_기존_쩜_탐색_알고리즘.md)·[12계율](./12계율_쩜_충돌_및_정보_갱신_알고리즘.md) |
| 일반 단어나 일회성 잡음 | 빈 결과 | [1계율](./1계율_쩜_추출_알고리즘.md) |
| 파일명 노출 또는 고위험 정보 | 보호 판단 전 보류 | [13계율](./13계율_개인정보_및_민감정보_처리_알고리즘.md) |
| 스냅샷에서만 등장했다 사라짐 | 잠정 후보 취소 | 최종 발화 재판단 |
| 저장소 접근 실패 | 신규 여부를 모름 | 오류 전달·재시도 판단 |

출력은 “왜 새 쩜이 필요한가, 어떤 근거를 담는가, 무엇이 미확정인가”라는 판단 기록이다.
예시: “새 장소 후보 / 사용자 개인 경험 확인 / 기존 쩜 불일치 / 파일명 보호 필요”.
이 기록은 새 API 계약이나 JJum의 추가 필수 필드가 아니다.
저장에 실패했다면 생성 완료라고 보고하지 않는다.
관련 이름을 해결하지 못했다면 쩜선 없이 보류하거나 확인을 요청한다.

## 보류 · 실패 처리

- 의미가 분명하지 않은 표현을 일반 지식으로 억지 해석하지 않는다.
- 같은 이름의 여러 인물을 하나로 합치거나 사실을 섞지 않는다.
- 기존 쩜을 읽지 못했는데 새 쩜으로 대체하여 중복을 만들지 않는다.
- 요약 생성 실패가 사실·사건의 지어내기로 이어지지 않게 한다.
- 사용자 데이터나 고위험 개인정보를 파일명에 그대로 노출하지 않는다.
- 파일 쓰기 실패, 잘못된 스키마, 손상된 인덱스를 성공으로 알리지 않는다.
- meta 내용을 읽고 서비스별 생성 규칙을 몰래 적용하지 않는다.
- 스냅샷의 잠정 후보를 최종 확정 기록이라고 표시하지 않는다.

## 가상 상황

### 예시 1 · 첫 개인 취향

사용자: “나는 민초를 먹으면 항상 별로야.”
탐색: 같은 개인 취향을 가리키는 쩜이 확인되지 않음.
판단: 민초 비선호에 개인적 의미가 있으므로 새 쩜 후보가 된다.
주의: “민초”라는 일반 단어의 사전 설명을 새 쩜으로 만들지 않는다.

### 예시 2 · 기억할 만한 장소

사용자: “성수의 그 카페에서 면접 떨어진 날 혼자 앉아 있었어.”
탐색: 해당 카페와 사건의 기존 쩜이 없음.
판단: 장소와 사건을 각각 기억할지 검토하고, 연결 근거가 있다면 쩜선을 검토한다.
주의: 부정적 경험이어도 저장 대상에서 자동 제외하지 않는다.

### 예시 3 · 실명과 파일명

사용자: “홍길동은 오래 알고 지낸 친구야.”
탐색: 다른 대상이라는 근거까지 확인해 새 쩜이 필요함.
판단: 내부 jjumName은 “홍길동”으로 두되 파일명은 보호 규칙에 따라 가린다.
주의: 마스킹된 파일명이나 실명을 jjumId로 사용하지 않는다.

### 예시 4 · 모호한 별명

사용자: “핑크가 그 얘기했어.”
탐색: 저장 쩜에 핑크라는 사람이 둘 있고 어느 쪽인지 알 수 없음.
판단: “핑크 선배”라는 호칭이 붙어도 다른 맥락의 두 사람 중 하나로 임의 확정하지 않는다.
판단: 임의 생성·병합하지 않고 확인 질문 재료를 남긴다.
주의: 의미가 비슷하다는 이유로 어느 한 사람의 사실을 가져오지 않는다.

### 예시 5 · 의미 불명 표현

사용자: “샤갈! 오늘 진짜 샤갈이네.”
탐색: 개인적 표현인지 일반 고유명칭인지 확인할 근거가 없음.
판단: 뜻을 멋대로 정하지 않고, 기억에 중요하다면 호스트에게 확인을 맡긴다.
주의: 화가 이름이라고 단정한 쩜을 생성하지 않는다.

## 검수 기준

- [1계율](./1계율_쩜_추출_알고리즘.md)의 개인적 의미와 [2계율](./2계율_기존_쩜_탐색_알고리즘.md)의 중복 판단을 거친다.
- 최종 발화와 스냅샷 후보를 분리하고 저장 성공 여부를 구별한다.
- jjumId가 자동 고유 ID이며 이름·파일명에서 만들지 않는다.
- 내부 jjumName과 보호된 파일명을 혼동하지 않는다.
- v4 jjtags와 schemaVersion=4를 사용하고 새 필수 필드를 만들지 않는다.
- facts·events·context는 근거를 보존하며 meta를 해석하지 않는다.
- 관련 이름을 targetId 또는 refJJumIds의 가짜 ID로 쓰지 않는다.
- 같은 이름이나 유사한 뜻만으로 자동 통합하지 않는다.
- 실패·모호함·민감정보를 성공한 생성으로 포장하지 않는다.

## 기획 근거와 미확정 항목

- [최신 기획서](../해마.ai_최신기획서.md)의 4단계 ⓘ와 4계율은 개인 맥락의 신규 쩜을 요구한다.
- [v4 스키마](../SCHEMA.md)는 필드와 파일명 보호 규칙의 단일 기준이다.
- [사용 시나리오](../USAGE_SCENARIOS.md)의 핑크·성수 카페·부정 사건은 새 쩜 예시다.
- [2계율](./2계율_기존_쩜_탐색_알고리즘.md)은 기존 쩜과 비교하고 [3계율](./3계율_기존_쩜_업데이트_알고리즘.md)은 확인된 기존 쩜을 갱신한다.
- 적용 기준: 기획서의 감정 의미 단위는 현재 감정 단독 쩜 생성으로 해석하지 않는다. 상세 감정 관계 데이터 구조는 미확정이다.
- 미확정: 입력 중 잠정 후보의 세부 영구 저장 시점.
- 미확정: 영문 고유명칭 파일명의 상세 마스킹 방식.
- 미확정: 개인 경험을 여러 쩜과 하나의 사건 중 어디까지 나눌지의 구체적 기준.
