1. ## 해마.ai 개요 

  1) ### 해마.ai 정의

    **해마.ai는 AI에게 인간의 해마와 같은 장기기억 및 연상 기능을 제공하는 별도 오픈소스 모듈입니다.**

  대화 속 개인화된 정보를 최소 단위인 **쩜(JJum)** 으로 구조화하여 저장하고, 쩜 사이의 **쩜선(Seon)** 을 형성하여 기억 간의 관계와 연상을 관리합니다.

  이를 통해 호스트 AI가 과거의 대화와 개인화된 기억을 필요한 순간에 다시 회상하고 활용할 수 있도록 합니다. 

  2) ### 해마.ai 역할

    AI와 인간의 관계. 어떻게 정의되고 있나요?

    해마.ai의 최종 지향점은

    **AI가 사람을 기억하고 관계를 이어갈 수 있도록** 

    **‘해마’의 역할을 합니다.** 

    

  * 호스트 AI가 나눈 대화를 기억합니다.  
  * 사람과 경험에 대한 기억을 쌓고 연결합니다.  
  * 지금의 대화에 필요한 과거의 기억을 떠올립니다.  
  * 호스트 AI의 대화 결과를 유저의 반응을 통해 학습합니다.  
  * 기억을 바탕으로 호스트 AI가 더 자연스럽고 개인화된 관계를 이어가도록 돕습니다.

  해마.ai는 특정 서비스나 도메인에 종속되지 않는 **범용 인공 해마**로서, 어떤 AI든 사람과 오래 관계를 이어가는 **‘찐친’ 같은 AI**로 발전할 수 있도록 돕습니다. 

  3) ### 해마.ai 의 기술적 비전

  해마.ai는 단순한 대화 저장소가 아니라, **기억과 관계를 연결하고 현재의 맥락에 맞는 기억을 스스로 연상하는 인공 해마**를 지향합니다. 사용자와의 대화뿐 아니라 **호스트 AI가 놓인 환경과 경험을 함께 축적**하여, AI가 자신의 맥락을 이해하고 스스로를 형성해갈 수 있는 기반을 제공합니다. 

  궁극적으로는 누구나 자신의 AI 서비스에 **복잡한 기억 시스템을 직접 구현하지 않고 해마.ai를 손쉽게 연결해 사용할 수 있도록 하는 것**을 목표로 합니다.

2. ## 핵심 개념

  1) ### 기억 구조

  * **쩜 (JJum)** — AI가 장기적으로 기억하는 최소 단위의 정보  
    * 쩜이름 (JJum Name) — 쩜을 식별하는 대표 이름  
    * 별칭 (Aliases) — 같은 대상을 다르게 부르는 이름  
  * **쩜선 (Seon**) — 쩜과 쩜 사이의 연관 관계  
    * Weight — 두 쩜의 연결 강도를 나타내는 값  
    * Label — 쩜선의 관계 유형  
    * lastActivated — 해당 쩜선이 마지막으로 활성화된 시점  
  * **쩜태그 (JJ-tag)** — 쩜의 유형·상태·의미·감정 등을 나타내는 표식
    * Cue — 특정 기억을 떠올리게 하는 단서
    * Valence — 감정의 방향과 강도
  * **인기 쩜 (Popular JJum)** — 많은 쩜선과 연결되거나 반복적으로 활성화되는 쩜. 단, 연결이 많다는 이유만으로 관련 기억 전체가 회상되는 것은 아니다.

  2) ### 기억 관리와 연상

  * **쩜통 (JJumBase)** — 쩜과 쩜선을 저장하고 관리하는 해마.ai의 기억 저장소  
  * **활성도 (Activation)** — 특정 기억이나 연상 경로가 현재 얼마나 활성화되어 있는지를 나타내는 값  
  * **감쇠 (Decay)** — 시간과 사용 빈도, 연상 거리 등에 따라 기억이나 연결의 활성도를 점진적으로 조절하는 과정  
    * **시간 감쇠** — 시간이 지나며 활성도가 낮아지는 현상  
    * **연상 거리 감쇠** — 현재의 키 쩜에서 멀리 떨어진 쩜일수록 연상 영향력을 낮추는 방식  
    * **사용 기반 강화** — 반복적으로 함께 회상되는 쩜선의 연결 강도를 높이는 방식  
  * **키 쩜 (Key JJum)** — 현재 대화에서 기억 탐색을 시작하는 핵심 쩜  
  * **회상 (Recall)** — 현재 대화의 단서와 키 쩜을 기준으로 관련 기억을 탐색하고 필요한 기억을 불러오는 과정

  3) ### 호스트 AI 연동

  * **호스트 AI (Host AI)** — 해마.ai를 연결하여 유저와 실제 대화를 수행하는 외부 AI 서비스 또는 에이전트  
  * **논블로킹 쓰로틀 (Non-blocking Throttle)** — 유저의 입력과 대화를 방해하지 않으면서 일정한 간격으로 대화 내용을 분석하고 기억 추출을 처리하는 방식  
  * **답변 가이드** — 해마.ai가 회상한 기억과 대화 맥락을 호스트 AI가 답변에 활용할 수 있도록 전달하는 지침  
    * Mode — 공감·축하·안부 등 답변의 대화 방향  
    * Comfort Cues — 답변에 활용할 수 있는 기억·감정 단서  
    * Forbidden — 사용하지 않아야 할 기억이나 답변 방식  
    * Follow-up Questions — 대화를 이어가기 위한 질문 후보  
  * **답변 평가** — 유저의 후속 반응을 바탕으로 호스트 AI의 이전 답변 결과를 평가하고, 이후 기억·회상·답변 가이드에 반영하는 과정

  4) ### 프라이버시 및 보안

  * **개인 식별 정보 절삭(PII Redaction)** — 기억으로 저장하기 전에 불필요하거나 고위험인 개인정보를 식별하고 제거하고 부분 마스킹하는 과정  
    * **Precision PII Truncation** — 대화 맥락에 필요한 범위만 남기고 과도한 개인정보의 정밀도를 낮추는 방식  
    * 예시 1: 전화번호 일부 ‘\*\*’로 교체.  
    * 예시 2:상세 주소는 번지수·동·호수 등을 제거하고 필요한 경우 동/구 수준의 지역 정보만 저장  
  * **E2EE (End-to-End Encryption)** — 유저의 기억 데이터를 종단간 암호화하여 복호화 키가 없는 제3자가 원본 데이터를 열람할 수 없도록 하는 방식  
  * **Zero-Knowledge** — 서버 운영자나 인프라 제공자가 유저의 기억 원본이나 복호화 키를 알 수 없도록 설계하는 보안 구조

  2) ### 해마.ai 핵심 13 알고리즘  계율

    #### **1\. 쩜 단위 추출 알고리즘**

  - 일반적인 단어의 사전적 의미가 아닌 사용자 개인에게 의미가 있는 정보를 추출  
  - 사실 / 선호 / 경험 / 관계 / 사건 / 감정 / 습관 등의 의미 단위 판단  
  - 하나의 발화에서 여러 쩜을 추출할 수 있어야 함

    #### **2\. 기존 쩜 탐색 알고리즘**

  - 신규 추출 정보와 기존 쩜의 의미적 유사성 비교  
  - 동일 쩜인지, 기존 쩜의 업데이트인지, 완전히 새로운 쩜인지 판단  
  - 충돌하거나 모순되는 정보 처리

    #### **3\. 쩜 업데이트 알고리즘**

  - 기존 쩜에 새로운 사실 추가  
  - 기존 정보의 변경 / 정정  
  - 시간에 따른 정보 변화 기록  
  - 쩜의 신뢰도 및 중요도 갱신

    #### **4\. 쩜 생성 알고리즘**

  - 신규 쩜의 제목 / 핵심 내용 / .jj 메타데이터 생성  
  - 사용자 개인 맥락을 유지한 형태로 저장  
  - 일반적인 지식이나 사전적 의미가 쩜으로 생성되지 않도록 필터링

    #### **5\. 감정 변화 / 망설임 탐지 알고리즘**

  - 입력 시간 간격 분석  
  - 타이핑 속도 변화 분석  
  - 이전 스냅샷과 현재 스냅샷 비교  
  - 감정 변화 가능성이 있는 지점 판단  
  - 판단 결과를 관련 쩜에 반영

    #### **6\. 회상 알고리즘**

  - 현재 발화에서 필요한 쩜 탐색  
  - 관련도 / 중요도 / 최신성 등을 기준으로 회상 대상 결정  
  - 너무 많은 쩜을 전달하지 않도록 회상 범위 제한

    #### **7\. 답변 가이드 생성 알고리즘**

  - 현재 대화 컨텍스트 \+ 회상된 쩜 결합  
  - 호스트 챗봇이 참고할 정보 생성  
  - HAEMA가 직접 답변하지 않고 호스트 챗봇에게 전달할 정보만 생성

    #### **8\. 호스트 답변 평가 알고리즘**

  - 호스트 챗봇의 실제 답변 분석  
  - 현재 대화 맥락과의 적합성 평가  
  - 회상된 쩜이 적절하게 반영되었는지 평가  
  - 다음 유저 발화에 활용할 정보 추출

    #### **9\. 미래 대화 탐색 알고리즘**

  - 현재 대화에서 가능한 미래 상황 탐색  
  - 여러 가능한 대화 경로 생성  
  - MTCS 기반 미래 탐색  
  - 탐색 결과를 쩜 및 회상 전략에 활용  
  - 기존 쩜통과 관계파일, 사용자 개성등 환경을 이해하고 쩜 탐색

    #### **10\. 쩜 중요도 / 우선순위 알고리즘**

  - 현재 대화와의 관련성  
  - 사용자 중요도  
  - 최신성  
  - 반복 언급 여부  
  - 감정적 중요도  
  - 회상 필요성 등을 종합하여 우선순위 결정

    #### **11\. 세션 상태 관리 알고리즘**

  - 활성 / 입력 중 / 대기 / 비활성 / 종료 상태 관리  
  - 타이핑 중단 시간에 따른 상태 전환  
  - 세션 복구 및 재개 처리

    #### **12\. 쩜 충돌 및 정보 갱신 알고리즘**

  - 기존 쩜과 새로운 발화가 서로 다른 정보를 포함하는 경우 처리  
  - 최신 정보 우선 여부 판단  
  - 과거 정보를 삭제하지 않고 변경 이력을 유지할 필요가 있는지 결정

    #### **13\. 개인정보 및 민감정보 처리 알고리즘**

  - 쩜 생성 전 개인정보 탐지  
  - 고위험 PII 탐지 및 Redaction  
  - 저장해서는 안 되는 정보 필터링  
  - 사용자 정보의 저장 / 회상 범위 제어

5. ## 📐 해마.ai 시스템 아키텍처

  1) ### 전체 시스템 구성

  - **Host AI** — 해마.ai가 연결되어 기억 기능을 제공하는 외부 AI 서비스 또는 에이전트(예: 마이풉 등).  
  - **해마.ai** — Host AI에 장기기억 및 연상 기능을 제공하는 인공 해마.  
  - **Proxy Server** — 해마.ai의 인증 및 보호된 시스템 컨텍스트를 관리하는 중계 서버  
    - `[M4+]` 사용 환경 정보  : 호스트 AI 정보, 호스트 서비스 정보 연결  
    - `[완료]` 절대계율, 해래본   
  - **Local Memory Storage** — 유저의 내 컴퓨터/기기에 쩜과 관계 데이터를 저장하는 장기기억저장소 (🧠장기기억저장소\_feat.해마🧠).  
  - **Algorithm / System Documents** — 해마.ai의 동작 원칙과 세부 알고리즘을 정의하는 문서  
    


  2) ### `[M4+]`  Host AI ↔ 해마.ai 통신 구조

  - Host AI와 해마.ai는 대화 데이터를 주고받으며, 해마.ai는 필요한 기억과 답변 가이드를 Host AI에 전달한다.

  > 해마.ai는 직접 대화하지 않고 Host AI의 뒤에서 기억을 담당한다.

  3) ### 프록시 및 인증 구조

      
  - Proxy Server는 Host AI와 해마.ai 사이의 요청을 중계하며, 해마.ai의 인증과 보호된 시스템 컨텍스트를 관리한다.  
  - 절대계율과 해례본 등 인간 개발자에게 노출 시키지 않는 문서를 프록시 서버로 전달.  
  - **`[M4+]`사용 환경 정보** : 호스트 AI 및 호스트 서비스와의 연동 상태 메타데이터를 관리한다. 

  4) ### 데이터 경계 (로컬 vs 서버) 

  - **원칙**: 유저의 기억 원본(**쩜**)은 **로컬 저장소**에 우선 저장하여 개인정보와 주권을 보장.  
  - **서버 역할**: 서버는 오직 인증 및 통신 요청·응답 데이터만 처리, 기억 원본과 명확한 경계 유지.  
  - **미래 확장 `[M4+]`**: PC웹과 모바일웹을 넘나드는 다중 환경(예: 마이풉)을 위해 추후 서버 암호화 저장 모듈 고려.  
  - **현재 개발 상태**: 호스트 챗봇 연동 전 단계, 엔드유저가 로컬 웹 콘솔을 통해 직접 사용해 보는 환경으로 개발을 진행.  
    


  5) ### 암호화 및 전자서명 구조

      
  - **목적**: 해마.ai 본연의 코어 정체성이 오염되거나 외부로 유출되는 것을 엄격히 차단. 

  - **위·변조 방지**: 통신 데이터와 시스템 핵심 문서에 암호화 및 전자서명을 적용.

  - **현재 환경 및 세션 컨텍스트** — 현재 연결된 Host AI, 사용자 관계, 대화 및 실행 환경을 전달한다.

    #### **정체성 복기 (Identity Re-anchoring)**

    - 긴 대화로 초기 정체성이 약화될 경우, **절대계율과 해례본을 다시 참조하여 정체성과 원칙을 복기**할 수 있다.  
    - 이는 재학습이 아니라 **“나는 누구이며 무엇을 위해 존재하는가”를 다시 고정하는 과정**이다.  
    - 필요한 시점에 선택적으로 복기한 후, 현재 세션의 작업을 이어간다.    

  4) ### 알고리즘 문서 탐색 및 확장 원칙

  - 해마.ai는 모든 알고리즘을 한 번에 입력받지 않는다.

  - 현재 작업에 필요한 알고리즘 문서를 찾아 참조하며, 기존 문서에 해결 방법이 없을 경우 절대계율에 어긋나지 않는 새로운 알고리즘을 제안·확장할 수 있다.

7. ## 개인정보 및 보안 설계

  1) ### Privacy-First 원칙

    - 사용자의 기억과 개인정보를 최우선으로 보호하며, 필요한 정보만 최소한으로 처리한다. 

  2) ### `[M1]`고위험 PII Redaction 절삭 및 마스킹

    - 기억 생성 단계에서 고위험 개인정보를 탐지하고 불필요한 식별 정보는 절삭·마스킹한다. 

  3) ### `[M4+]` E2EE

      
    - 기억 데이터를 종단간 암호화하여 사용자 외 제3자가 원본을 열람할 수 없도록 한다. 

  4) ### `[M4+]`Zero-Knowledge

      
    - 서버 운영자나 인프라 제공자가 사용자의 기억 원본과 복호화 키를 알 수 없는 구조를 지향한다. 

  5) ### `[M4+]`기억 데이터의 소유권과 접근 권한

    - 기억 데이터의 소유권은 사용자에게 있으며, 접근 및 활용 권한을 명확하게 관리한다. 

  6) ### `[M4+]`사용자 열람 및 데이터 관리

      
    - 사용자가 자신의 기억 데이터를 직접 열람하고 관리할 수 있도록 한다.

8. ## 호스트 AI 연동 규격

  1) ### `[M4+]` Host AI 연결 방식

   - 해마.ai와 외부 Host AI 간의 연결 및 인증 방식을 정의한다. 

  2) ### `[M1]` 입력 데이터 규격

    - Host AI가 해마.ai에 전달하는 **사용자 발화와 현재 대화에 필요한 기본 컨텍스트의 구조**를 정의한다.


      - 사용자 발화 원문 또는 현재 입력 중인 Snapshot  
      - 사용자 및 세션 식별 정보  
      - 현재 대화의 이전 발화 및 필요한 대화 컨텍스트  
      - Host AI 및 서비스의 환경 정보  
      - 입력 시점의 타임스탬프

    
    - 예시:

    |  {   "user\_input": "지난번에 추천해준 카페 진짜 좋았어.",   "timestamp": "2026-09-16T14:32:10",   "session\_id": "session\_001",   "host\_id": "mypoop" }  |
    | :---- |


  3) ###  `[M1]`회상 데이터 규격

    - 해마.ai가 현재 대화와 관련성이 높다고 판단한 **쩜과 쩜선, 관련 기억 정보**를 Host AI가 활용할 수 있는 형태로 전달하는 구조를 정의한다.


      - 현재 대화와 관련된 회상 쩜  
      - 회상 쩜과 연결된 쩜선 및 관계 정보  
      - 현재 대화와의 관련성 및 회상 우선순위  
      - 답변에 활용할 수 있는 필요한 기억의 맥락

    - 예시:

    | {   "recalled\_jjums": \[     {       "name": "카페\_추천",       "content": "사용자는 조용하고 분위기 좋은 카페를 선호함",       "tags": \["선호", "카페"\],       "relevance": 0.92     },     {       "name": "지난번\_카페",       "content": "지난번에 추천받은 카페를 사용자가 실제로 방문함",       "relation": "카페\_추천",       "relevance": 0.87     }   \] }  |
    | :---- |

    - 회상 데이터는 현재 대화에 필요한 \*\*회상 쩜과 관련 관계 정보\*\*로 구성되며, Host AI에 전달되어 답변에 활용된다.


  4) ###  `[M4+]`Response Guide 규격

    - 회상된 기억과 현재 맥락을 바탕으로 Host AI의 답변에 활용할 가이드의 구조와 전달 방식을 정의한다.

  5) ### `[M4+]`Host Response 전달 및 평가

    - Host AI의 실제 답변을 전달받고, 사용자 반응을 바탕으로 답변 결과를 평가하여 이후 기억과 관계 정보에 반영한다. 

  6) ### `[M4+]`호스트별 관계 데이터 관리

    - Host AI마다 사용자와 형성된 관계 정보와 상호작용 데이터를 구분하여 관리한다.

10. ## 개발 마일스톤

    

1) ### M1. 핵심 기능 구현 — 일단 돌아가게 만들기                    
     
   **목표: HAEMA의 핵심 기능을 하나의 완전한 흐름으로 구현한다.**  
   **가정: 호스트 챗봇이 없는 상태로 진행. 테스터(나 혼자)는 호스트 챗봇과 대화하는 상황 가정하고 진행**

  1) AI API 연결  
  2) 대화 입력 수신  
  3) 쩜 생성  
  4) 쩜 조회 및 회상  
  5) 쩜 수정  
  6) 쩜 저장 및 불러오기  
  7) 기획서에 정의된 데이터 구조와 핵심 동작 구현

   **완료 기준:**

   `대화 입력 → AI 분석 → 쩜 생성/조회/수정 → 저장/불러오기 → 회상`

   위 핵심 흐름이 실제로 정상 동작해야 한다.

   ---

2) ### M2. 로컬 시뮬레이션 테스트

   **목표: 실제 호스트 챗봇 사용 상황을 가정하여 HAEMA의 회상 기능을 검증한다.**  
   **가정: 호스트 챗봇이 없는 상태로 진행. 테스터(나 혼자)는 호스트 챗봇과 대화하는 상황 가정하고 진행.**  
- **웹 콘솔에서 사용 할것**


  1) 개인용 로컬 테스트 서버 구축  
  2) 실제 호스트 챗봇과 연결하지 않는다.  
  3) 사용자가 호스트 챗봇과 대화하고 있다고 가정하여 테스트한다.  
  4) HAEMA는 직접 대화하지 않는다.  
  5) HAEMA가 회상한 쩜을 **호스트 챗봇에게 전달하는 상황을 시뮬레이션**한다.  
  6) 쩜 생성, 회상, 수정 및 전달 흐름을 검증한다.

   **완료 기준:**

   가상의 호스트 챗봇과 대화하는 상황에서 HAEMA의

   `쩜 생성 → 저장 → 회상 → 호스트 챗봇에게 전달`

   흐름이 정상적으로 작동해야 한다.

   ---

3) ###  M3. GitHub Pages 공개 \+ 소수 테스터

   **♥️나는 여기쯤에서 마이풉개발로 다시 간듸아♥️**

   **목표: 제한된 사용자에게 HAEMA를 공개하여 실제 사용 피드백을 확보한다.**

   **환경: 깃헙 페이지 서비스로 웹콘솔 접속**

  1) GitHub Pages 서비스 공개  
  2) 테스터용 로컬 서버 폴더 및 실행 환경 제공  
  3) 소수의 테스터에게 배포  
  4) 실제 사용 과정에서 발생하는 오류 및 UX 문제 수집  
  5) 테스터 피드백을 반영하여 기능 안정화

   **완료 기준:**

   외부 테스터가 정해진 절차를 통해 HAEMA를 설치하고 직접 테스트할 수 있어야 한다.

   ---

4) ###   M4. 개발자 커뮤니티 공개 \+ 실제 호스트 챗봇 연동

   **목표: 실제 개발 환경에서 HAEMA를 사용할 수 있도록 공개한다.**

  1) 실제 호스트 챗봇과 HAEMA 연동  
  2) 개발자 커뮤니티 공개  
  3) 설치 및 연동 방법 문서화  
  4) 다양한 개발 환경에서 사용할 수 있도록 개선  
  5) 버그 리포트 및 사용자 피드백 대응

   **완료 기준:**

   개발자가 자신의 호스트 챗봇에 HAEMA를 연결하여 실제 사용할 수 있어야 한다.

   ---

5) ### M5. 비개발자 바이브 코더 지원

   **목표: 개발 지식이 부족한 사용자도 HAEMA를 쉽게 설치하고 사용할 수 있도록 진입 장벽을 낮춘다.**

  1) 설치 과정 단순화  
  2) 설정 과정 단순화  
  3) 비개발자용 사용 가이드 제공  
  4) 주요 설정 자동화  
  5) 오류 발생 시 이해하기 쉬운 안내 제공  
  6) 다양한 호스트 챗봇 및 개발 환경 지원

   **완료 기준:**

   비개발자 바이브 코더가 별도의 개발 지원 없이 HAEMA를 설치하고 기본 기능을 사용할 수 있어야 한다.
