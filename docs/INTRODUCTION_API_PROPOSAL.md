# 자기소개·호칭 저장 API 제안 — 백엔드 연결 대기

대표님 요청으로 작성한 **프론트 제안 계약**이다. 현재 구현된 백엔드 API를 뜻하지 않는다. 백엔드 담당이 구현하거나 다른 계약을 확정하면 해당 내용에 맞춰 프론트 연결부를 조정한다. 기존 코어·스키마·서버는 수정하지 않았다.

## 화면과 요구 동작

- 저장소 버튼 왼쪽에 `👤: 자신을 소개해주세요`를 표시한다. 클릭하면 줄글 입력 모달을 연다.
- textarea placeholder는 정확히 `챗봇에게 당신에 대해 알려주세요! 어떻게 불러드릴까요?`다. 줄바꿈과 원문을 보존한다.
- 저장된 자기소개가 있으면 버튼은 `👤: {{displayName}}`이 된다. 프론트는 본문을 정규식 등으로 분석해 이름을 고르지 않는다.
- 사용자가 원하는 호칭을 명시하면 그것을 우선한다. 없으면 해마.ai가 문맥에서 호칭 **한 가지**를 정한다. 정보가 부족하거나 호칭 정리에 실패하면 `사용자`를 쓴다. 호칭은 저장할 때 결정해 보관하며 단순 조회·렌더링마다 AI를 호출하지 않는다.
- 자기소개가 없을 때 버튼은 소개 요청 문구이며, 챗봇의 기본 호칭은 `사용자`다. 호스트에 실제 자기소개와 호칭을 전달하는 처리는 백엔드 연결 과제이며 UI 저장만으로 적용됐다고 주장하지 않는다.

## 저장 범위

- 현재 서버가 연결한 저장소의 `storageId`와 인증/기존 사용자 범위의 `ownerId`로 격리한다. 자기소개는 API키·모델을 바꿔도 같은 사용자·저장소에 유지한다.
- 서버가 실제 저장소의 엔드유저 관계 데이터 영역을 선택한다. 브라우저가 보낸 임의 파일 경로나 이전 File System Access 핸들을 신뢰하지 않는다. 자기소개 원문과 정한 호칭을 일반 쩜으로 강제 변환하지 않는다.
- 요청의 `storageId`가 서버의 현재 연결 ID와 다르면 읽기·쓰기를 거부한다. 원자적 저장 및 기존 데이터 보존은 서버에서 보장한다. 저장 전 status 조회만으로 다른 저장소에 쓰는 일을 막을 수는 없다.
- 최초 조회는 파일을 만들거나 AI를 호출하지 않는다. 실패·충돌이면 이전 저장값을 보존한다. 원문을 조용히 자르거나 줄바꿈·공백을 임의 정리하지 않는다.

## 제안 HTTP 계약

조회: `GET /api/owners/:ownerId/introduction?storageId=불투명ID`

저장: `PUT /api/owners/:ownerId/introduction`

```json
{
  "storageId": "file:synthetic-storage",
  "text": "저는 합성 예시 사용자예요. 합성호칭으로 불러주세요.\n두 번째 문단입니다.",
  "revision": 0
}
```

조회와 저장 성공 응답:

```json
{
  "success": true,
  "ownerId": "synthetic-owner",
  "storageId": "file:synthetic-storage",
  "introduction": {
    "text": "저는 합성 예시 사용자예요. 합성호칭으로 불러주세요.\n두 번째 문단입니다.",
    "displayName": "합성호칭",
    "revision": 1,
    "updatedAt": "2026-10-20T05:40:00.000Z"
  }
}
```

- 최초 미등록 조회는 HTTP200이며 `text:""`, `displayName:"사용자"`, `revision:0`, `updatedAt:null`로 반환한다. 404는 미등록 데이터의 의미로 사용하지 않는다.
- 저장 요청의 revision은 조회한 버전이다. 현재 버전과 다르면 HTTP409로 거부하며 원본을 유지한다. 성공 시 revision은 요청보다 증가한 안전한 정수, updatedAt은 서버가 실제 부여한 ISO8601 시각이다. 불확실한 네트워크 실패 후에는 먼저 재조회하고 내용을 확인하며 자동 PUT 재시도는 하지 않는다.
- 성공 응답의 ownerId/storageId는 요청 대상과 정확히 같고 text는 보낸 원문과 같아야 한다. displayName은 앞뒤 공백·줄바꿈·제어문자가 없는 단일 문자열이다. 현재 프론트 검증 상한은 Unicode 코드포인트512개이며 화면에서는 긴 이름을 말줄임하고 전체 이름은 버튼 title로 제공한다. 본문 길이에 임의 프론트 상한은 두지 않았다.
- 저장소 불일치·동시 수정은409, 저장소 미연결·권한·입력·저장 실패는 적절한 오류로 전달한다. 오류 응답을 저장 성공으로 표시하지 않는다. 프론트는404/405/501을 API 준비 중 상태로 다루고 초안을 유지한다.
- 현재 UI는 비어 있거나 공백뿐인 새 본문을 저장하지 않는다. 삭제 버튼이나 기존 소개의 자동 삭제는 이번 요청에 포함하지 않았다. 서버의 빈 값 처리 정책을 달리 정하면 인계한다.

## 현재 프론트와 확인할 내용

`web-console/haema-introduction.js`는 이 제안 응답을 검증한다. 모달은 선택 저장소 신원을 요청 전후 대조하고, 서버가 준비되지 않았거나 실패한 경우 초안을 탭의 sessionStorage에 보존한다. 입력 원문을 localStorage에 영구 저장해 서버 저장으로 대신하지 않는다.

백엔드 담당은 실제 저장 파일·권한·충돌 처리, 호칭 선정과 기본값, 호스트 전달 경로, 필요한 해마 내부 AI 호출의 사용량 연계 및 실제 서버 전달 방법을 인계한다. 프론트는 없는 토큰 수치를 추정하거나 같은 호출을 중복 합산하지 않는다. 구현 후 실제 API의 저장→재조회→서버 재시작·재연결과 사용자/저장소 격리를 함께 확인해야 한다.
