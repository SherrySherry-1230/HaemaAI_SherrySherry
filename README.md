# 🦭 Haema — 호스트 챗봇의 해마

> **An artificial hippocampus for the host chatbot.** 호스트가 대화 상대와 경험을 기억하고 연상하도록 돕는 범용 기억 모듈이다.
> 하나의 대화창에는 언제나 사용자 한 명만 있다. 사용자 쩜은 호스트가 그 상대를 기억하는 쩜이다.
>점과 선은 한국어에서 비유적으로 너무 자주쓰는 단어라 서비스 개념 편의를 위해 쩜과 쩜선으로 한글 표기한다. 
**용어** — 기억의 최소 단위는 **쩜**(코드 `JJum`), 쩜 사이 연관은 **쩜선**(`Seon` — "점이 선에 선을 문다"),
쩜에 달린 표식은 **JJ-tag**(쩜태그, `jjtags` — 긍정/중립/부정 valence도 JJ-tag의 한 종류), 대화가 끊길 때 던질 화제는 **이야깃거리**.

---

## 🧠 왜 만들었나

대화가 끝나면 AI는 오늘 만난 사람도, 같이 웃었던 사건도 잊는다.
"기억 데이터를 넣어줘도 안 쓰는" 문제는 저장이 아니라 **회상(꺼내 쓰는 타이밍)** 의 문제였다.

Haema는 호스트의 기억을 묶고 색인을 만들며, 현재 대화의 단서에서 관련 기억을 연상하도록 돕는다.

## ✨ 무엇을 하나

| | |
|---|---|
| 🔖 **쩜(JJum)** | 기억의 최소 단위. 인물·장소·사건·표현… 하나가 쩜 하나 (`JJum`) |
| 🏷️ **자동 추출** | 대화에서 의미 있는 생각·기억의 단위를 쩜으로 만든다 |
| 🔗 **쩜선(Seon)** | 두 쩜 사이의 연결 강도를 weight로 관리한다. 새 7단계 기준은 아래의 v5 기획을 따른다 |
| 🎯 **선별 회상** | 현재 대화에 필요한 쩜을 골라 호스트에게 전달한다. 구현 상태와 최신 기획은 PLAN·SCHEMA에서 구분한다 |
| 🧬 **별칭 통합** | "핑크" = "박**"임을 알게 되면 하나로 합친다. 틀리면 되돌린다 |
| 🌙 **자동 정리** | 안 쓰는 기억은 삭제가 아니라 잠든다. 다시 언급되면 깨어난다 |
| 🤐 **환각 방지** | 기억이 없으면 빈 결과. 지어낼 재료를 주지 않는다 |

## 🧩 어떻게 쓰나

Haema는 **기억을 만들고 넘겨주는 소프트웨어**다. 말하는 건 당신의 챗봇이 한다.

### 👀 이런 식으로 움직인다

> 유저: "오늘 비 오니까 이상하게 그 카페 생각난다"
> AI: "성수에 있던 카페? 너 거기서 면접 떨어진 날 혼자 앉아 있었다고 했잖아"

감정+장소+사건이 선을 문 연상 — **검색이 아니라 연상임을 체감하는 순간.**
사용자가 먼저 꺼낸 기억을 호스트가 알아봐 주는 예다.

## 오늘 정리한 점수 기준 — v5 기획

현재 구현·파일 검증은 v4다. 아래는 2026-10-08에 정리한 기획·스키마·파이프라인 기준이며 코어 코드와 기존 파일의 이행 완료를 뜻하지 않는다.

**쩜 파워 = 언급 점수 항 + 노출 기간 점수 항 + 감정 총량 점수 항 + 쩜선 점수 항.** 양의 정수로 표시하고 상한 없이 갱신하는 계획이다. 현재 확정된 언급식은 `α × log_β(N)`, N≥1이며 나머지 세 항의 환산식은 미정이다.

- **N:** 사용자가 먼저 의미상 해당 쩜을 가리킨 발화 횟수. 호스트가 먼저 꺼낸 쩜에 따라 답한 경우는 제외한다. 일반적인 질문에 답하면서 사용자가 새 쩜을 먼저 꺼낸 경우는 집계한다. 같은 발화·같은 쩜은 별칭과 반복 표현을 합쳐 최대 1회다.
- **생략된 자기 지칭:** “오늘도 이렇게 복잡한 생각하기 겁내고 있다”처럼 `나`가 없어도 자기 생각·상태를 먼저 말한 경우 사용자 쩜을 1회 집계한다.
- **생성 기본값:** 일반 쩜과 사용자·호스트 자아쩜 모두 N=1로 시작한다. 일반 생성 발화는 중복 집계하지 않고 대화 전 생성한 자아쩜의 첫 실제 선행 사용자 언급은 N=2가 된다.
- **α·β:** α↑면 점수가 커지고 β↑면 작아지며 둘은 같은 세로 배율에 작용한다. N=β일 때 점수는 α다. 완성한 29개 타입 로그식 표의 현재 사용자 α=1·β=7, 호스트 α=3·β=2를 보존한다. 소수 제한과 α=1의 정합성, 복수 타입 평균 적용 방식은 미정이다.
- **노출 기간·감정:** 사용자 자신은 출생부터로 최대 기간, 부모는 긴 기간을 기본 추정한 뒤 대화로 보정한다. 감정 총량은 긍정·부정을 상쇄하지 않으며 단발과 오래 지속되는 도트뎀·도트힐을 포함한다.
- **호스트 관점:** 높은 사용자 쩜 파워를 매번 “너는 어때?”라는 질문으로 연결하지 않는다. 상대 이해의 배경과 현재 화제를 구분하고 파워·회상 점수·직접 언급 적절성을 각 목적에 맞게 사용한다.

**쩜선은 공동 언급으로 생성할 때 양쪽 weight=4.0이다.** 이후 공동 언급 누적이나 호스트가 연관해 실제로 언급한 것에 대한 사용자 긍정 피드백으로 대응 연결을 함께 강화한다. 0~1 미만은 연관 없음, 1~2 미만부터 6~7 미만은 1~6단계, **7.0 이상은 모두 7단계이며 원점수에는 상한이 없다.** 소수점을 보존한다. 기존 +0.1·최대 1·하루 −0.01·최소 0.1 규칙은 새 기획에서 폐기했으며 강화 증가량과 v4 이행은 미정이다.

## 타입별 계수표와 CSV

[계수표](https://docs.google.com/spreadsheets/d/1T3MACATKMU_mZNewSMqJ5kj2tszxbYmyEeODyF4MF9I/edit?gid=0#gid=0)는 `type_id,type_name,alpha,beta,description` 형식으로 내보낸다. type_id는 표의 No이며 1은 사용자·2는 호스트다. 사용자 칸에 닉네임을 넣어도 No를 유지하여 같은 설정을 찾는다.

Apps Script는 gid=0의 실제 타입 행만 UTF-8 BOM CSV로 내보내며, 제목·작성자·그래프·HEX 참고 행은 제외한다. 코드 저장과 CSV 메뉴·다운로드 창을 확인했다. 인앱 브라우저의 최종 다운로드 파일 저장과 코어 CSV 연동은 확인·구현 완료로 표시하지 않는다.
